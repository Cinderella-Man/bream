# Process-owned state outside the process heap

Source review, 2026-10-07. Reference: OTP `29.1.1`, commit `ad05823719d77c8faee87348ea39513d4e2f99c5`. This bounded review traces ETS ownership, inheritance and exit cleanup, plus port connection/link lifetime. **No tests, experiments or builds were run.** ETS and ports remain outside Bream's initial admitted state. These are resource-lifetime lessons, not a proposal to implement ETS, port drivers or bundled utilities.

## ETS has an owner even when other processes can access it

An ETS table is not garbage-collected when its last Erlang reference disappears. Its creating process initially owns it; explicit deletion or owner termination destroys it unless ownership transfers. A shared table therefore has two different concepts: access and responsibility for its lifetime. Merely importing a Rust concurrent map would not reproduce this contract. [Documented lifetime](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/lib/stdlib/src/ets.erl#L71-L76).

`erts_db_process_exiting` walks the process's owned-table list. After locking a table it rechecks ownership, because another operation could have changed it. It attempts inheritance only when the heir is neither `none` nor the exiting owner. Otherwise it revokes access, marks deletion, cancels the table's outstanding trap continuation, removes any registered name and clears the table identifier before continuing reclamation. [Exit state machine](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/beam/erl_db.c#L5030-L5104); [local entry](/home/bat/projects/bream/upstream/otp/erts/emulator/beam/erl_db.c:5030).

`give_away_to_heir` locks the recipient and table in the required order, retrying/rechecking after dropping the table lock. An absent heir fails transfer; a process with a reused PID also fails because the stored `heir_started_interval` must match the current process incarnation. `set_heir` records that interval, or normalizes an already nonexistent recipient to `none`. Successful inheritance moves the table between ownership lists before notification. With `{heir, Pid, Data}` it copies a transfer message into the heir's message ownership; `{heir, Pid}` intentionally produces no transfer message. [Identity and transfer branches](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/beam/erl_db.c#L4861-L4971), [heir registration](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/beam/erl_db.c#L5319-L5359), [notification contract](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/lib/stdlib/src/ets.erl#L1272-L1283).

Explicit `give_away/3` requires the caller to own the table and the recipient to be a live, local, different process. It changes ownership before sending `ETS-TRANSFER`; it preserves the configured heir. Thus a giver can nominate itself as heir, give away its table and inherit it back later. Ownership transfer is not contingent on the recipient executing a receive clause. Concurrent recipient death still needs an interleaving-sensitive oracle: transfer may fail before commitment, or succeed followed by the new owner's cleanup. [Public contract](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/lib/stdlib/src/ets.erl#L473-L482), [native checks and commit](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/beam/erl_db.c#L3087-L3143).

## Reclamation survives interruption

Explicit deletion by an authorized non-owner first transfers cleanup ownership to that deleting process. This is deliberate: if the deleter is killed while table destruction has yielded, its exit cleanup must finish the job. Deletion disables inheritance. `free_table_continue` retains ownership while there is work left, removing it only after the table-specific destruction continuation finishes. [Delete transition](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/beam/erl_db.c#L3023-L3076), [continuation completion](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/beam/erl_db.c#L5400-L5425).

The process exit path preserves an explicit cleanup continuation across scheduler turns. ETS cleanup has `GET_OWNED_TABLE`, `FREE_OWNED_TABLE` and `UNFIX_TABLES` phases; the last releases this process's table-fixation registrations even for tables it does not own. This proves resumable cleanup exists, not a universal wall-clock bound on each nested operation. Table algorithms were intentionally not audited. [Cleanup continuation and fixations](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/beam/erl_db.c#L4974-L5143), [process exit integration](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/beam/erl_process.c#L14356-L14368).

## Port connection is separate from links

For linked process death, process cleanup schedules a broken-link exit to the port. The receiver verifies the link still exists before delivering it. A normal linked exit is ignored when its sender is neither the connected process nor the port itself; an exit from the current connected process closes the port even with reason `normal`. Other reasons close it. This is a link-mediated lifetime relationship, not unconditional destruction whenever a stored owner PID becomes dead. [Process-side exit](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/beam/erl_process.c#L14084-L14099), [link validation](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/beam/io.c#L2187-L2199), [exit branches](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/beam/io.c#L3830-L3952).

`port_connect/2` links the new owner but leaves the former owner's link intact. The asynchronous connect-message form updates the connected PID without creating that new link. Connection metadata alone therefore cannot explain failure propagation. Closing can retain native state while queued output drains; for a newly accepted exit, reason `kill` bypasses that drain branch. An already closing/exiting port rejects another exit in the traced handler. Port disappearance does not promise termination of an arbitrary external program: the manual qualifies that program's cooperation. [Connect contract](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/preloaded/src/erlang.erl#L12017-L12057), [distinct native paths](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/beam/io.c#L2323-L2400), [external-program boundary](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/system/doc/reference_manual/ports.md#L31-L43).

## Additional planned branch cases

`RES-01` records process-owned external-state lifetime. All six cases are **planned reference/admission work**, not accepted ETS/port implementation scope. Dependencies: `REF-02` fixtures, `LANG-02` admitted resources, `LIFE-05` kill/reclamation and `EXEC-03` cleanup. Any shared-table feature needs an explicit Rust access, ownership-transfer and cleanup design first.

| Case | Trigger and expected branches | Forbidden outcome and proposed acceptance check |
|---|---|---|
| RES-01.C01 | Last table reference disappears with owner alive; separately owner dies without a usable heir. First table remains; second enters deletion. | Forbid reference-count lifetime masquerading as owner lifetime. Check table visibility before/after the owner exit with a retained test identifier. |
| RES-01.C02 | Owner dies with live heir, with and without heir data. Ownership transfers in both; only the data form sends `ETS-TRANSFER`. | Forbid requiring message consumption to commit ownership, or synthesizing notification for the silent form. Check access and mailbox separately. |
| RES-01.C03 | Heir absent at configuration, dies later, equals exiting owner, or PID is reused. No transfer to an unrelated incarnation. | Forbid resurrection or transfer by numeric PID alone. Exercise dead/reused identity fixtures; concurrent death permits transfer-then-cleanup or failed transfer followed by deletion. |
| RES-01.C04 | Owner gives away to live different local PID; contrast self/dead/non-owner/invalid table. Success transfers and preserves heir; invalid operations fail. | Forbid partial ownership changes on failure or deleting a successfully transferred table when the former owner dies. Verify transfer-back and heir round trip. |
| RES-01.C05 | Kill owner or authorized non-owner during large-table deletion; also exit with fixations on another owner's table. Cleanup continues with retained responsibility. | Forbid orphaned destruction, inheritance of a deleting table, or permanent dead-process fixations. Observe cleanup rescheduling and eventual resource return; do not equate one yield with bounded latency. |
| RES-01.C06 | Reconnect a port, then deliver old/new owner linked exits; compare BIF versus message connection and output-draining versus `kill` closure. | Forbid treating connection and link sets as identical or promising external-program death. Separate metadata/link checks, accepted exit outcomes and native cleanup completion; race with close permits documented failure. |

## Evidence coverage and remaining limits

Read upstream `heir`/PID-reuse, silent-heir and `give_away` assertions, plus `evil_delete` and exit-rescheduling fixtures. The latter requires repeated exit scheduling under its chosen workload; it establishes no universal latency guarantee. Port connect/close race tests were sampled, including their allowed `badarg` outcome. [Heir fixtures](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/lib/stdlib/test/ets_SUITE.erl#L3468-L3515), [silent and explicit transfers](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/lib/stdlib/test/ets_SUITE.erl#L3592-L3683), [interrupted deletion](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/lib/stdlib/test/ets_SUITE.erl#L4665-L4725), [exit scheduling assertion](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/lib/stdlib/test/ets_SUITE.erl#L4880-L4940), [port race](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/test/port_SUITE.erl#L3061-L3074).

Not reviewed: table algorithms, complete lock/race state space, driver-specific shutdown, native callbacks or OS backends. Notification provenance and priority interaction require the existing messaging model; an Erlang tuple's shape is not proof of runtime origin. Resource reactor lifetime is covered separately in [report 22](22-process-io-native-boundary.md). Bream's useful lesson is to keep ownership, accessibility, notification and reclamation as distinct tracked transitions.
