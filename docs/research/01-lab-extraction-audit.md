# Source-lab extraction audit: existing Wasm machinery

**Scope clarification:** this report audits what already exists in the source laboratory. The user subsequently made native Rust preemption an explicit requirement, recorded in [ADR 0001](../adr/0001-native-preemptive-processes.md). The Wasm extraction ideas below apply to a different potential product; they are not Bream's implementation recommendation. For Bream the principal conclusion is that there is **no native preemptive engine to extract** from this lab. Preserve its evidence and separation lessons, while investigating a native engine separately.

Inspected 2026-10-07. Repository: `/home/bat/projects/rust-actor-runtime-lab`, clean tracked/untracked status at commit `f78658b08faaea84b7c9e7bb3a2dab13fafc17c7`. Read-only inspection; no source changes or large qualification reruns. This report separates existing behavior, retained observations, and proposed design.

## Verdict

There is a credible independent library inside the experiments, but it is an **execution and process-lifecycle layer around Wasmtime**, not a new scheduler and not an implementation of preemptive arbitrary native Rust closures. The clearest extraction is the duplicated `Guest` envelope: compiled-module loading, one resident Store per instance, a byte-buffer ABI, metered async execution, memory limits, and instance disposal. The lab already has two unrelated domain workloads using this pattern. Tokio schedules the resulting futures; Kameo supplies ownership, mailboxes and supervision. [Resident execution envelope](/home/bat/projects/rust-actor-runtime-lab/experiments/resident-rust/host/src/lib.rs:89), [portable execution envelope](/home/bat/projects/rust-actor-runtime-lab/experiments/portable-component/host/src/main.rs:13), [dependencies](/home/bat/projects/rust-actor-runtime-lab/experiments/resident-rust/host/Cargo.toml:9).

The existing code could support a separate Rust/Wasm library, but that would not satisfy Bream's native-execution requirement. The lab does not establish a drop-in `spawn(|| arbitrary_native_rust())` API with preemptive scheduling. Its tests and architectural separation are the relevant reusable assets for the native project.

## What the current program actually does

1. `Environment` creates one Wasmtime Engine with fuel instrumentation, optionally compact memory mappings, compiles four fixed modules, and rejects every import. Modules are shared by guest instances. Artifact compilation happens before the measured Tokio loop. [Environment](/home/bat/projects/rust-actor-runtime-lab/experiments/resident-rust/host/src/lib.rs:44), [startup](/home/bat/projects/rust-actor-runtime-lab/experiments/resident-rust/host/src/main.rs:371).
2. Each `Guest` owns a separate `Store`, linear-memory handle and typed allocator/invoke exports. A 16 MiB per-memory limit, one memory, one instance, and trapping growth failure are configured. Fuel is replenished per invocation; the async yield interval is 10,000 fuel units. [Instantiation and policy](/home/bat/projects/rust-actor-runtime-lab/experiments/resident-rust/host/src/lib.rs:99).
3. Calls encode a concrete domain `Command` as JSON, allocate input in guest memory, copy it, invoke asynchronously, copy output back, free the two buffers, and decode the domain reply. The whole guest call sequence shares the per-invocation fuel budget. `MAX_WIRE` is 8 MiB here; the later portable fixture uses 512 KiB. [Resident calls](/home/bat/projects/rust-actor-runtime-lab/experiments/resident-rust/host/src/lib.rs:145), [portable calls](/home/bat/projects/rust-actor-runtime-lab/experiments/portable-component/host/src/main.rs:54).
4. Real typed Rust state lives in a guest `RefCell` across calls and has no `Serialize`, `Deserialize` or `Clone` implementation. Only explicit snapshots export the whole state. Commands still incur encoding and copies; residency does not mean zero-copy messaging. [Resident state](/home/bat/projects/rust-actor-runtime-lab/experiments/resident-rust/guest/src/lib.rs:24), [snapshot dispatch](/home/bat/projects/rust-actor-runtime-lab/experiments/resident-rust/guest/src/lib.rs:328).
5. `Resident` is a Kameo actor containing `Guest`. It serializes handling, distinguishes typed domain errors from boundary failures, turns every boundary failure into owner panic, and relies on Kameo transient supervision to restart a fresh V1 guest. A new diagnostic generation is allocated; the Kameo reference remains stable. [Owner](/home/bat/projects/rust-actor-runtime-lab/experiments/resident-rust/host/src/lib.rs:223), [failure policy](/home/bat/projects/rust-actor-runtime-lab/experiments/resident-rust/host/src/lib.rs:262), [supervision](/home/bat/projects/rust-actor-runtime-lab/experiments/resident-rust/host/src/lib.rs:486).

## Preemption: strong evidence, narrow contract

The resident fixture does establish useful **guest-level preemption from the application author's perspective**. A ten-million-iteration Rust guest loop has no inserted `.await`; Wasmtime's instrumentation yields the suspended invocation, an independent Kameo heartbeat actor progresses on the same Tokio current thread, and the original computation finishes in the same generation. The test requires at least three heartbeats during work. This is resumption, not merely trapping a runaway and then executing someone else. [Guest loop](/home/bat/projects/rust-actor-runtime-lab/experiments/resident-rust/guest/src/lib.rs:290), [fairness fixture](/home/bat/projects/rust-actor-runtime-lab/experiments/resident-rust/host/src/main.rs:186), [single-thread runtime](/home/bat/projects/rust-actor-runtime-lab/experiments/resident-rust/host/src/main.rs:380).

Retained final default qualification records 36 heartbeat replies during 109.08 ms of work, maximum observed heartbeat gap 3.34 ms. Final compact qualification records 24 replies during 74.58 ms, maximum observed gap 3.25 ms. Those are observations from two specific runs, not guaranteed latency, scheduler throughput or performance comparisons. [Default evidence](/home/bat/projects/rust-actor-runtime-lab/evidence/resident-rust/qualification-final/result.json), [compact evidence](/home/bat/projects/rust-actor-runtime-lab/evidence/resident-rust/qualification-compact-final/result.json).

Important limits:

- The quantum is fuel, not milliseconds. There is a finite total budget separate from the quantum. Reaching a quantum yields/resumes; exhausting the total budget fails the instance. The current public fixture lets a caller choose invocation fuel, so a reusable API must decide who is authorized to choose policy. [Configuration](/home/bat/projects/rust-actor-runtime-lab/experiments/resident-rust/host/src/lib.rs:115), [budget refresh](/home/bat/projects/rust-actor-runtime-lab/experiments/resident-rust/host/src/lib.rs:148), [fixture Execute](/home/bat/projects/rust-actor-runtime-lab/experiments/resident-rust/host/src/lib.rs:457).
- Host JSON encoding/decoding, buffer copies, snapshot comparison and module compilation are ordinary synchronous Rust outside guest fuel metering. All guest imports are forbidden, so blocking native host calls and async I/O are not qualified at all. [Call envelope](/home/bat/projects/rust-actor-runtime-lab/experiments/resident-rust/host/src/lib.rs:145), [import prohibition](/home/bat/projects/rust-actor-runtime-lab/experiments/resident-rust/host/src/lib.rs:64).
- Yielding allows other actors to run; it does not make the *busy actor* process its own next mailbox message, inspection or upgrade. Its handler still awaits the active invocation. A separate control path capable of stopping that invocation is absent. [Execute handler](/home/bat/projects/rust-actor-runtime-lab/experiments/resident-rust/host/src/lib.rs:461), [Inspect handler](/home/bat/projects/rust-actor-runtime-lab/experiments/resident-rust/host/src/lib.rs:358).
- No custom run queue, work stealing, priority scheduling, multi-worker fairness or tenant accounting is implemented in these sources. Their scheduling contribution is Wasmtime configuration and async calls; actual task scheduling comes from Tokio.
- The older `wasm-boundary` fixture only traps an infinite loop and runs an independent actor afterward. It is containment evidence, not concurrent fairness evidence. It uses WAT guests and host-owned counter snapshots rather than resident Rust state. [Older probe](/home/bat/projects/rust-actor-runtime-lab/experiments/wasm-boundary/src/main.rs:122).

## What to extract, and what to keep outside

| Candidate | Existing evidence | Recommended treatment |
|---|---|---|
| Engine/module preparation | Shared Engine and compiled Modules, import rejection | Extract as prepared program/cache layer. Remove hardcoded names `v1`, `v2`, `reject`, `bad_abi`; separate compilation from runtime admission. |
| Per-process execution | `Guest`, typed exports, async fuel and limiter | Extract as private execution backend with explicit limits and terminal failure state. |
| Guest ABI adapter | Owned buffers, resident state, command dispatch | Extract/generated SDK hides allocator ABI and serializes typed application messages; lower-level transport is bytes. |
| Process reference and mailbox | Kameo `ActorRef`/`Message`; serial actor owner | Specify generic process semantics independently; retain Kameo as prototype adapter or choose it deliberately as dependency. Do not expose all Kameo types accidentally. |
| Supervision | Transient restart, bounded restart rate | Optional higher layer. Explicitly choose incarnation addressing and restart-version policy. |
| Snapshot migration | Separate candidate Store, validation before publication, explicit 64-entry queue | Preserve as example/extension until a generic schema and policy contract is designed. Current verification literally compares counts, balance hundredths, ballast and pending tool maps. |
| Portable application core | `State::handle(Command) -> Reply`, no actor/OS/Wasm coupling | Keep as conformance example demonstrating library independence. It is a domain library, not the runtime itself. |
| Elixir Port transport and Phoenix Clock | Packet framing, fixture aborts/delays, domain clock algorithms | Keep out of runtime core. Optional interoperability packages/examples. |

Sources: [resident runtime and migration](/home/bat/projects/rust-actor-runtime-lab/experiments/resident-rust/host/src/lib.rs:44), [domain-specific migration verification](/home/bat/projects/rust-actor-runtime-lab/experiments/resident-rust/host/src/lib.rs:408), [portable application core](/home/bat/projects/rust-actor-runtime-lab/experiments/portable-component/core/src/lib.rs:1), [portable guest adapter](/home/bat/projects/rust-actor-runtime-lab/experiments/portable-component/guest/src/lib.rs:1), [Port transport](/home/bat/projects/rust-actor-runtime-lab/experiments/portable-component/transport/src/lib.rs:1).

The portable experiment is particularly useful architecture evidence: the unchanged domain crate runs directly as native Rust and behind the Wasm envelope. It proves that application logic can be kept independent of execution machinery. It does **not** prove equal native/Wasm isolation or scheduling: native dispatch calls `State::handle` directly; guest dispatch is metered. Both are driven by a serial Port loop and outer OTP supervision in the scenario. Despite the name “portable component,” this uses core Wasm modules and a handwritten ABI, not WIT or the WebAssembly Component Model. [Native adapter](/home/bat/projects/rust-actor-runtime-lab/experiments/portable-component/native/src/main.rs:24), [Wasm host](/home/bat/projects/rust-actor-runtime-lab/experiments/portable-component/host/src/main.rs:108), [guest exports](/home/bat/projects/rust-actor-runtime-lab/experiments/portable-component/guest/src/lib.rs:9).

## “Tiny” is a target, not an established capacity claim

The strongest retained density observation is 1,000 initialized resident guest Stores with no written ballast: about 58.91 MiB extra RSS, 27.66 MiB extra PSS, 17.70 GiB extra virtual size with compact reservations, and 1,125 MiB total accessible linear memory. These are different accounting quantities. Dividing the RSS delta gives roughly 60 KiB per guest in this run; it is not a universal process allocation size. With 128 KiB written ballast each, RSS rises to 183.92 MiB. Default reservations yield about 4,064 GiB virtual size for 1,000 guests while RSS stays about 58.92 MiB. [Density evidence](/home/bat/projects/rust-actor-runtime-lab/evidence/resident-rust/density-summary.json).

The density loop creates `Guest`s in a Vec; it does **not** create one Kameo mailbox, supervisor, active call, socket or network stack per instance. Module compilation is outside the baseline, the engine and modules are shared, native binaries are debug builds, guest binaries are release/LTO, and prior async call history affects retained resources. No million-process or BEAM-density claim follows. [Density algorithm](/home/bat/projects/rust-actor-runtime-lab/experiments/resident-rust/host/src/main.rs:332), [build profiles](/home/bat/projects/rust-actor-runtime-lab/experiments/resident-rust/README.md:15).

A 16 MiB linear-memory limit is not a 16 MiB host-RSS limit. Output buffers, host message queues, decoded objects, compiled code, stacks and runtime metadata add costs. Snapshot export/import also increases accessible guest capacity. Admission must account for more than `memory_size`; table elements, host buffers, artifact size/compilation, concurrent in-flight calls, queued message bytes and aggregate runtime limits need explicit treatment in a general library. These are design gaps inferred from the current concrete policy, not failures the experiment claims to solve. [Current limiter](/home/bat/projects/rust-actor-runtime-lab/experiments/resident-rust/host/src/lib.rs:100), [host allocations](/home/bat/projects/rust-actor-runtime-lab/experiments/resident-rust/host/src/lib.rs:145), [size interpretation](/home/bat/projects/rust-actor-runtime-lab/docs/resident-rust.md:46).

## Correctness work required before exposing this as a reusable library

1. **Make failed/cancelled instances uncallable by construction.** `Guest::call(&mut self)` returns an error but leaves `Guest` available; safety currently depends on `Resident::invoke` panicking so the whole owner drops. An external library consumer could accidentally reuse a partially mutated instance. A runtime-owned process state machine must enforce retirement after traps and after interrupted invocation cleanup. Cancellation/drop semantics are not tested. [Guest call](/home/bat/projects/rust-actor-runtime-lab/experiments/resident-rust/host/src/lib.rs:145), [owner disposal policy](/home/bat/projects/rust-actor-runtime-lab/experiments/resident-rust/host/src/lib.rs:263), [mutation before trap](/home/bat/projects/rust-actor-runtime-lab/experiments/resident-rust/guest/src/lib.rs:377).
2. **Separate rejected requests, typed application errors, process exits and infrastructure faults.** The owner currently fails on all boundary errors, including failures that occur before guest entry. Public semantics should distinguish admission rejection from uncertain partial execution and preserve useful exit reasons. [Error conversion](/home/bat/projects/rust-actor-runtime-lab/experiments/resident-rust/host/src/lib.rs:180), [invoke](/home/bat/projects/rust-actor-runtime-lab/experiments/resident-rust/host/src/lib.rs:263).
3. **Define mailbox and lifecycle contracts.** The explicit 64-entry queue only applies during a prepared upgrade, counts messages rather than bytes, has no lease or abort, and is bypassed by `Execute`. It is not complete overload handling. No guest-initiated spawn/send/receive APIs exist: current guests are resident message handlers called by a host. A “tiny process” API with blocking-style receive, links, monitors and child processes requires new ABI/runtime machinery. [Prepared queue](/home/bat/projects/rust-actor-runtime-lab/experiments/resident-rust/host/src/lib.rs:314), [Execute bypass](/home/bat/projects/rust-actor-runtime-lab/experiments/resident-rust/host/src/lib.rs:457), [guest command surface](/home/bat/projects/rust-actor-runtime-lab/experiments/resident-rust/protocol/src/lib.rs:8).
4. **Add an out-of-band control plane.** Kill/cancel/observe must work while a process has a long running call or a full mailbox. Fairness between runnable guests does not itself provide process control. Current inspect is an ordinary message. [Inspect](/home/bat/projects/rust-actor-runtime-lab/experiments/resident-rust/host/src/lib.rs:358).
5. **Keep external effects explicit.** Current import-free guests return typed intents; a harness task supplies completions. There is no generic async host import, child task ownership, cancellation, retry reconciliation or transactional effect system. Adding these changes the threat/resource model and cancellation contract. [Intent types](/home/bat/projects/rust-actor-runtime-lab/experiments/resident-rust/protocol/src/lib.rs:68), [documented scope](/home/bat/projects/rust-actor-runtime-lab/docs/resident-rust.md:75).
6. **Treat upgrade as an extension.** Current code is a convincing message-boundary state migration example, but no general invariant checker, active-stack migration, coordinator recovery or snapshot headroom guarantee exists. Candidate isolation does not save an active instance whose snapshot export traps. [Commit](/home/bat/projects/rust-actor-runtime-lab/experiments/resident-rust/host/src/lib.rs:384).
7. **Build with arbitrary guest applications, not only bundled trusted fixtures.** Buffer-pointer handling, ABI validation, reply decoding, start functions, unusual module memories/tables and intentionally malicious allocator exports need an adversarial contract suite. Safe Wasmtime memory access protects the host range access, but the current tests do not qualify a hostile-module SDK. Native serialization must be bounded before allocating potentially large representations where practical. [Resident ABI](/home/bat/projects/rust-actor-runtime-lab/experiments/resident-rust/guest/src/lib.rs:404), [later portable pointer checks](/home/bat/projects/rust-actor-runtime-lab/experiments/portable-component/host/src/main.rs:54).

## Useful next evidence gates

These are proposed experiments, not completed work:

- Extract the envelope with no counter/Clock/Elixir/Kameo types in its lowest public API; run both existing domains unchanged through it.
- Run several simultaneously CPU-bound guests plus latency-sensitive guests on one worker; record p50/p99/max latency, work share, memory and throughput while varying fuel quantum.
- Demonstrate an ordinary guest loop can be stopped by runtime control while it has an active handler; verify instance retirement and host resource cleanup after cancellation.
- Measure complete process cost including mailbox, incarnation handle, supervisor policy and resident/suspended stack. Vary idle versus in-flight calls, message sizes, process churn, written memory and snapshot load; include saturation/admission failure.
- Define byte-bounded mailboxes and result semantics under full mailbox, caller timeout, actor exit, restart and stale handle use. Check simultaneous send/exit races.
- Add one controlled async host capability and prove it preserves scheduler progress, explicit cancellation and process ownership; isolate or reject blocking native callbacks.
- Run local multithreaded and shutdown conformance before discussing a replacement executor or distributed runtime.
