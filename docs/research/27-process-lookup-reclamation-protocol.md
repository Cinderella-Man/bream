# Process lookup and reclamation: identity, temporary access, and record ownership

Research snapshot: 2026-10-07. Read-only review of **OTP 29.1.1**, commit `ad05823719d77c8faee87348ea39513d4e2f99c5`. **No runtime execution, upstream tests, failure injection, or memory-model verification was performed.** This report traces local process-table publication, lookup, lock acquisition, retirement and selected retained owners. It extends [lifecycle cleanup](/home/bat/projects/bream/docs/research/20-process-lifecycle-deep-dive.md) and [execution ownership](/home/bat/projects/bream/docs/research/18-process-execution-memory-deep-dive.md); it does not prove all ERTS callers correct.

The essential distinction is threefold: **PID equality identifies an incarnation; thread progress protects a temporary lookup; locks and explicit references protect different subsequent operations.** None substitutes for the others. In particular, a reference to the `Process` record does not imply that the process is live or that its heap still exists.

## 1. Publication and slot reuse

`early_init_process_struct` initializes the PID, atomic state, run-queue association and initial signal-buffer pointer, then initializes **all process locks held**. `erts_ptab_new_element` reserves an ID, calls this initializer, initializes the record reference count to one, and publishes the pointer with a release operation. This publishes an early skeleton, not every final process field: `alloc_process` and creation continue initialization while the locks remain held. [Early initialization and allocation](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/beam/erl_process.c#L12159-L12218) · [local](/home/bat/projects/bream/upstream/otp/erts/emulator/beam/erl_process.c:12159) [Reference initialization and publication](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/beam/erl_ptab.c#L530-L558) · [local](/home/bat/projects/bream/upstream/otp/erts/emulator/beam/erl_ptab.c:530)

Deletion release-stores NULL into the slot, computes the next ID data by adding the table size, masks to the finite ID width and skips the invalid encoding. The next incarnation may occupy that slot while the old record remains allocated. Lookup derives a slot from the supplied PID, reads its pointer with a data-dependency barrier, then compares the **complete** stored PID. A slot index alone is insufficient. Full-ID wrap is still finite; do not turn this check into an eternal uniqueness promise. [Slot removal and next ID](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/beam/erl_ptab.c#L675-L720) · [local](/home/bat/projects/bream/upstream/otp/erts/emulator/beam/erl_ptab.c:675) [Raw and live-filtered lookup](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/beam/erl_process_lock.h#L1135-L1156) · [local](/home/bat/projects/bream/upstream/otp/erts/emulator/beam/erl_process_lock.h:1135)

The process table is initialized with `release_element = NULL`. Consequently, the generic deletion function's optional later-release callback is **not** the process-record retirement mechanism. Exit's DONE phase explicitly schedules the baseline-reference decrement later, after its own lifecycle work. [Process-table initialization](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/beam/erl_process.c#L758-L774) · [local](/home/bat/projects/bream/upstream/otp/erts/emulator/beam/erl_process.c:758) [Callback parameter](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/beam/erl_ptab.c#L359-L367) · [local](/home/bat/projects/bream/upstream/otp/erts/emulator/beam/erl_ptab.c:359) [Conditional generic release](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/beam/erl_ptab.c#L730-L734) · [local](/home/bat/projects/bream/upstream/otp/erts/emulator/beam/erl_ptab.c:730) [Actual process retirement](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/beam/erl_process.c#L14755-L14769) · [local](/home/bat/projects/bream/upstream/otp/erts/emulator/beam/erl_process.c:14755)

## 2. Lookup branches and revalidation

| Reader/path | Protection acquired | Result and obligation |
|---|---|---|
| `erts_proc_lookup_raw` | Existing thread-progress protection, asserted in lock-check builds | May return an EXITING record; neither locks nor an owned reference are acquired. Borrow cannot cross an unprotected progress boundary. |
| `erts_proc_lookup` | Same temporary protection | Rejects EXITING at its state check; does not freeze liveness after return. |
| `proc_lookup_inc_refc` | Unmanaged-delay guard where needed; increments record ref before releasing guard | Raw variant permits EXITING; filtered variant checks it. Owned allocation can outlive the live process. |
| `erts_pid2proc_opt`, no requested locks | Delay guard through lookup and optional ref increment | Its general branch skips the later EXITING recheck when `need_locks == 0`; callers must supply the correct record/operation protocol. |
| Same function, quick lock success | Requested process locks, optional explicit ref | Revalidates after acquisition; default rejects EXITING. |
| Same function, TRY_LOCK contention | No successful new lock ownership | Returns distinct `ERTS_PROC_LOCK_BUSY`, not an absent-process result. |
| Same function, blocking contention | Ordered lock acquisition; unmanaged caller temporarily retains record | Revalidates after waiting; intervening exit is not silently accepted as a live process. |

[Borrowed lookup](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/beam/erl_process_lock.h#L1135-L1156) · [local](/home/bat/projects/bream/upstream/otp/erts/emulator/beam/erl_process_lock.h:1135) [Guard-to-reference conversion](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/beam/erl_process_lock.c#L1000-L1028) · [local](/home/bat/projects/bream/upstream/otp/erts/emulator/beam/erl_process_lock.c:1000) [Lookup and quick-lock selection](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/beam/erl_process_lock.c#L847-L900) · [local](/home/bat/projects/bream/upstream/otp/erts/emulator/beam/erl_process_lock.c:847) [Contention and post-lock validation](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/beam/erl_process_lock.c#L917-L987) · [local](/home/bat/projects/bream/upstream/otp/erts/emulator/beam/erl_process_lock.c:917)

For an unmanaged blocking caller, the sequence is specifically: increment a temporary process ref, release the unmanaged thread-progress delay, acquire locks through `proc_safelock`, revalidate, then release the temporary ref. It avoids holding a global reclamation delay across a potentially long lock wait. `proc_safelock` may also release the caller's existing locks to respect inter-process/lock-rank order; before releasing its last lock on either process, an unmanaged caller adds a temporary ref, removed after reacquisition. Earlier observations under those released locks may therefore need caller-level rechecking. [Blocking lookup](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/beam/erl_process_lock.c#L934-L987) · [local](/home/bat/projects/bream/upstream/otp/erts/emulator/beam/erl_process_lock.c:934) [Lock-order contract](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/beam/erl_process_lock.c#L573-L605) · [local](/home/bat/projects/bream/upstream/otp/erts/emulator/beam/erl_process_lock.c:573) [Lock-to-reference handoff](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/beam/erl_process_lock.c#L700-L803) · [local](/home/bat/projects/bream/upstream/otp/erts/emulator/beam/erl_process_lock.c:700)

The final locked validation rejects EXITING by default. `ALLOW_OTHER_X` instead checks that the old pointer is **still the pointer in its table slot**: “allow exiting” does not mean “accept a record already removed from the table.” This complements the earlier PID comparison; it is not a new lookup of the replacement. Exit acquires all minor locks while holding MAIN before committing EXITING, so any correctly acquired process lock prevents that transition until released. Removal later also holds all process locks. [Revalidation predicate](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/beam/erl_process_lock.c#L970-L987) · [local](/home/bat/projects/bream/upstream/otp/erts/emulator/beam/erl_process_lock.c:970) [Exit-lock exclusion](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/beam/erl_process.c#L14190-L14197) · [local](/home/bat/projects/bream/upstream/otp/erts/emulator/beam/erl_process.c:14190) [Removal under locks](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/beam/erl_process.c#L14429-L14469) · [local](/home/bat/projects/bream/upstream/otp/erts/emulator/beam/erl_process.c:14429)

## 3. Ownership transition table

| Transition | Owner/protection before and after | What is no longer permitted |
|---|---|---|
| Allocate → publish | Creator holds all locks; initial count becomes one before table publication. | Unprotected consumers cannot read unfinished fields merely because the pointer is visible. |
| Borrow slot → inspect PID | Managed progress interval or explicit unmanaged delay protects record storage. | A matching PID does not authorize holding the pointer indefinitely. |
| Borrow → retained reference/locks | Increment or lock acquisition occurs before temporary protection ends; locks get post-acquisition validation. | Incrementing an already freed/zero-count record is not a recovery technique. |
| Live → EXITING | All-lock transition excludes live locked operations; exit continuation owns remaining cleanup. | Ordinary application execution cannot be resurrected by a stale scheduling record. |
| EXITING → removed/FREE | Slot is cleared; public-ID data may be reused; exit publishes FREE and continues relationship cleanup. | Table absence is not proof that every record owner has released. |
| Exit DONE → retired baseline | Schedules baseline decrement after thread progress; dirty/queue/native references may remain. | DOWN or slot removal alone cannot justify freeing the record. |
| Normal body deletion | `delete_process` releases queues, off-heap owners, heaps and dictionary while record may remain referenced. | Record-ref holders cannot infer heap access from allocation liveness. |
| Last reference → record free | Release decrement plus final barrier; `erts_free_proc` destroys locks, performs delayed body deletion if required, then frees record. | Neither stale readers nor waiters may remain without a protecting ownership path. |

## 4. Thread progress and ordering obligations

The internal documentation requires participating managed threads to reach a known state and execute a full memory barrier after an operation starts and before it completes. Its reclamation example explicitly requires borrowed references to be dropped before leaving the protected code. Normal schedulers register as managed; dirty CPU and dirty I/O schedulers register as **unmanaged**. Being a runtime thread does not itself grant implicit protection. [Thread-progress contract](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/internal_doc/ThreadProgress.md#L65-L121) · [local](/home/bat/projects/bream/upstream/otp/erts/emulator/internal_doc/ThreadProgress.md:65) [Normal registration](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/beam/erl_process.c#L8756-L8764) · [local](/home/bat/projects/bream/upstream/otp/erts/emulator/beam/erl_process.c:8756) [Dirty CPU registration](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/beam/erl_process.c#L8808-L8834) · [local](/home/bat/projects/bream/upstream/otp/erts/emulator/beam/erl_process.c:8808) [Dirty I/O registration](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/beam/erl_process.c#L8869-L8884) · [local](/home/bat/projects/bream/upstream/otp/erts/emulator/beam/erl_process.c:8869)

Relevant happens-before/protection edges are:

1. **Initialize → publish → dependent read.** Table publication is release; raw lookup uses ERTS's data-dependency read barrier. This is a C/runtime primitive contract, not permission to copy a relaxed `AtomicPtr` load into Rust and dereference it. A Rust design must prove publication and aliasing through its chosen primitives.
2. **Unpublish → grace period → baseline release.** A pre-existing managed borrow must finish before reclamation's progress target completes. The later target is derived with a full barrier and normally a two-step progress offset; normal scheduler updates provide the participation points. [Later target](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/beam/erl_thr_progress.h#L233-L262) · [local](/home/bat/projects/bream/upstream/otp/erts/emulator/beam/erl_thr_progress.h:233) [Scheduler update](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/beam/erl_process.c#L9857-L9865) · [local](/home/bat/projects/bream/upstream/otp/erts/emulator/beam/erl_process.c:9857)
3. **Unmanaged entry → validate bucket → lookup.** Entry reads the current counter bucket with acquire, increments it with acquire, and rereads the bucket; a switch causes decrement/retry. Exit decrements with release. The leader checks managed progress and outstanding unmanaged counters, switches buckets with StoreLoad ordering, then advances the global progress value using a full-barrier store. [Unmanaged entry/leave](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/beam/erl_thr_progress.c#L985-L1045) · [local](/home/bat/projects/bream/upstream/otp/erts/emulator/beam/erl_thr_progress.c:985) [Leader advancement](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/beam/erl_thr_progress.c#L704-L761) · [local](/home/bat/projects/bream/upstream/otp/erts/emulator/beam/erl_thr_progress.c:704)
4. **Reference handoff → last release.** Reference increment is a no-barrier operation because existing protection must already establish a valid record. Decrement is release; zero triggers a LoadLoad/LoadStore barrier before reclamation. The debug assertion expects an incremented count above one. Reference counting alone cannot make an unprotected pointer safe. [Counter ordering](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/beam/erl_ptab.h#L368-L384) · [local](/home/bat/projects/bream/upstream/otp/erts/emulator/beam/erl_ptab.h:368) [Final-decrement dispatch](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/beam/erl_process_lock.h#L1033-L1047) · [local](/home/bat/projects/bream/upstream/otp/erts/emulator/beam/erl_process_lock.h:1033)
5. **Lock acquisition → state revalidation → field use.** Ref ownership preserves storage; locks and operation-specific FREE/EXITING predicates authorize mutation. Retirement must also account for every queue/native owner, rather than equating “not in the table” with “no readers.”

The double-counter design prevents new unmanaged entrants continually extending the same waiting cohort. It does not supply a reclamation deadline if an old guard is never released or a managed participant fails to progress. This report has not formally verified weak-memory architectures, progress-counter wrap, or all wait/registration paths. [Unmanaged delay rationale](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/internal_doc/ThreadProgress.md#L260-L295) · [local](/home/bat/projects/bream/upstream/otp/erts/emulator/internal_doc/ThreadProgress.md:260)

## 5. Off-scheduler and scheduler-retained owners

`send_sig` uses raw lookup on normal schedulers and raw lookup plus a record ref otherwise. Its locked fallback checks FREE before accepting into the inbound queue, releases MSGQ, and eventually releases the non-normal caller's ref. The buffered fast path has its own protocol and is a remaining sub-audit: this report does not claim that the fallback check proves every buffer race safe. [Lookup, enqueue fallback and release](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/beam/erl_proc_sig_queue.c#L1168-L1249) · [local](/home/bat/projects/bream/upstream/otp/erts/emulator/beam/erl_proc_sig_queue.c:1168)

`deliver_result` similarly selects borrowed lookup or a no-lock `INC_REFC` lookup for off-scheduler delivery, delegates allocation/queueing to message helpers, then drops acquired locks and the record ref. The retained reference does not make those helpers' receiver-state checks optional. [Native result delivery](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/beam/io.c#L3303-L3345) · [local](/home/bat/projects/bream/upstream/otp/erts/emulator/beam/io.c:3303)

Queue ownership is explicit too. A proxy retains its real process and releases that ref when freed. Dirty enqueue increments **before** queue publication; same-dirty-queue rescheduling transfers its existing ownership instead of dropping/reacquiring it. Exit DONE may create an additional ref for an obsolete ordinary run-queue record, matched by a decrement when scheduling discards that inactive/FREE entry. [Proxy creation](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/beam/erl_process.c#L6436-L6482) · [local](/home/bat/projects/bream/upstream/otp/erts/emulator/beam/erl_process.c:6436) [Proxy destruction](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/beam/erl_process.c#L4056-L4065) · [local](/home/bat/projects/bream/upstream/otp/erts/emulator/beam/erl_process.c:4056) [Dirty queue transfer](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/beam/erl_process.c#L6826-L6894) · [local](/home/bat/projects/bream/upstream/otp/erts/emulator/beam/erl_process.c:6826) [Exit-side stale-record retention](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/beam/erl_process.c#L14714-L14745) · [local](/home/bat/projects/bream/upstream/otp/erts/emulator/beam/erl_process.c:14714) [Discard-side release](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/beam/erl_process.c#L10138-L10154) · [local](/home/bat/projects/bream/upstream/otp/erts/emulator/beam/erl_process.c:10138)

## 7. Proposed additional conformance and internal qualification cases

These nine **planned, unimplemented** cases extend the current LIFE-05.C01–C11 inventory; they do not select an epoch library or expand the initial worker count. Concurrent/internal cases couple to EXEC-07.C03; existing lifecycle specifications remain the semantic dependency. Instrumented pause points and owner counters are future test setup, not production API requirements.

| ID | Trigger and required/forbidden observation |
|---|---|
| LIFE-05.C12 | Pause a protected reader after slot load; remove process and publish a replacement. Old record remains readable only within protection; full-ID mismatch rejects replacement. No use-after-free or mistaken routing before full-ID reuse. |
| LIFE-05.C13 | Lookup blocks acquiring a process lock while target commits exit/removal. On acquisition revalidate; never return an ordinary live handle for the dead record. Explicit exiting-record operations must still reject removal. |
| LIFE-05.C14 | An unmanaged reader upgrades temporary protection to a record ref before blocking. Retirement can progress after guard release, but record cannot free before ref release. Audit every success/failure/TRY/flag branch for balanced ownership. |
| LIFE-05.C15 | Two-process ordered locking temporarily releases the caller's final lock. Preserve both allocations, reacquire in order, and revalidate observations whose protection was lost; forbid deadlock and stale field access. |
| LIFE-05.C16 | Retain a record through logical death and ordinary body cleanup. Live lookup stays absent and heap access stays forbidden; final ref release frees record exactly once. Record ref must not masquerade as process-state ownership. |
| LIFE-05.C17 | Death leaves proxy, dirty-queue or obsolete ordinary queue ownership. Drain each owner exactly once without executing dead application code; no early free, duplicate release or replacement resurrection. Dirty-native reference behaviour is reference evidence, not admission permission. |
| LIFE-05.C18 | Pause unmanaged entry during counter-bucket switch and during upgrade-to-ref. Every accepted lookup has continuous protection; failed entry retries release the old bucket; no unprotected gap or permanent artificial delay. |
| LIFE-05.C19 | Delay a managed participant or an unmanaged guard across retirement. Defer reclamation safely and account for retained storage; resume permits progress. No false cleanup-complete notification or invented latency bound. |
| LIFE-05.C20 | Force small test-only generation/progress counters and allocator-address reuse. Distinguish slot reuse, full public-ID reuse and pointer-address reuse; stale internal ownership cannot target the replacement. Verify wrap predicates independently of steady-state tests. |

Bream needs an explicit separation between live process access, retained dead-record metadata, and independently retained runtime resources. It can initially implement that separation more simply than ERTS; any later lock-free or multiworker optimization must preserve the same ownership transitions. This research is evidence for those obligations, not a Rust soundness certification.

Plan integration: these additional IDs are recorded in the [build plan](../build-plan.md); conditional scope and unexecuted ownership/interleaving obligations remain explicit.
