# Buffered signal publication and retirement during process exit

Research snapshot: 2026-10-07, **OTP 29.1.1**, commit `ad05823719d77c8faee87348ea39513d4e2f99c5`. This is a **read-only source audit**: no upstream execution, injected races, allocator measurements or weak-memory verification. It deepens [report19's publication trace](/home/bat/projects/bream/docs/research/19-process-signals-timers-deep-dive.md) and [report27's remaining buffer-lifetime gap](/home/bat/projects/bream/docs/research/27-process-lookup-reclamation-protocol.md). Existing exact-version observations elsewhere do not execute the internal transitions described here.

The main result: **buffer admission is governed by a per-slot alive check under its mutex, not a fresh receiver-liveness check.** A sender already protecting the process record can enqueue during the interval between receiver FREE and buffer deinstallation. Deinstallation must collect that ownership. Process-record retention, array retention, slot ownership, signal ownership and scheduler notification are separate parts of the protocol. One late-reinstallation branch remains unresolved below; this is not a complete reclamation proof.

## 1. Installation and two independent retained allocations

Buffers are available only with the off-heap message-queue state. Installation additionally requires no installed array and the contention heuristic, except the DEBUG configuration forces installation eligibility. The array has 64 mutex-protected slots, a nonempty bitmap, message/non-message summary flags, a baseline `dirty_refc` of one, and adaptation counters. The initializer fully initializes the array before release-publishing `sig_inq_buffers`. These are implementation choices, not semantic mailbox capacities. A caller must already protect the **Process** containing that pointer. In `proc_queue_signal`, normal schedulers use protected raw lookup; other threads obtain an explicit process-record ref, released after publication/failure. Array access then has its own protection: `get_buffers` starts unmanaged-delay protection and acquire-loads the pointer. Managed threads retain a temporary borrow; unmanaged readers increment the array ref before releasing the delay guard. Thus retaining the Process alone does not retain a replaced array. ## 2. Sender publication and ownership transfer

`try_enqueue_to_buffer` immediately declines if the sender already holds receiver MSGQ, or if no array is obtained. Otherwise it hashes the supplied ordering identity `from` into one slot, locks it and checks **slot.alive**. A dead slot returns failure after unlocking/ungetting; the caller still owns the unqueued signal sequence and must take its fallback. The array-wide alive flag is not this sender's admission gate. [Entry and locked validation](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/beam/erl_proc_sig_queue.c#L10261-L10306) · [local](/home/bat/projects/bream/upstream/otp/erts/emulator/beam/erl_proc_sig_queue.c:10261)

With a live slot locked, the sender sets type-summary flags and updates/reads the bitmap using full-barrier operations. It rechecks summaries and can restart if a concurrent flush cleared them. A nonempty slot whose bitmap bit has already been cleared is recognized as selected by an in-progress flush; that flusher will acquire this same mutex and collect the queued sequence. Then `enqueue_signals` appends the sequence and maintains non-message links/message-count offsets, and the sender releases the slot mutex. [Publication and metadata race](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/beam/erl_proc_sig_queue.c#L10308-L10379) · [local](/home/bat/projects/bream/upstream/otp/erts/emulator/beam/erl_proc_sig_queue.c:10308) [Sequence linking and flags](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/beam/erl_proc_sig_queue.c#L903-L962) · [local](/home/bat/projects/bream/upstream/otp/erts/emulator/beam/erl_proc_sig_queue.c:903)

A successful append transfers the signal sequence to receiver-owned transport. The sender subsequently notifies scheduling; it must not free or requeue the sequence merely because the receiver dies before notification. A failed buffered attempt transfers nothing. Control callers have type-specific failure handling: an alternate-action message frees its allocation after `proc_queue_signal` fails, while an is-alive request repurposes its allocation into a false reply to its requester. [Post-publication notification](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/beam/erl_proc_sig_queue.c#L10379-L10420) · [local](/home/bat/projects/bream/upstream/otp/erts/emulator/beam/erl_proc_sig_queue.c:10379) [Failed alternate message](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/beam/erl_proc_sig_queue.c#L2274-L2278) · [local](/home/bat/projects/bream/upstream/otp/erts/emulator/beam/erl_proc_sig_queue.c:2274) [Failed is-alive request](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/beam/erl_proc_sig_queue.c#L3060-L3070) · [local](/home/bat/projects/bream/upstream/otp/erts/emulator/beam/erl_proc_sig_queue.c:3060)

**The sender does not hold the slot mutex during notification.** If it observed no previously nonempty slots, it first waits for receiver MSGQ to be released. The receiver's empty-scan path keeps MSGQ locked into its wait transition; notification before that transition could otherwise be overwritten by sleep. Array and process protections remain valid through this wait and notification. [Wait-before-notify](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/beam/erl_proc_sig_queue.c#L10387-L10419) · [local](/home/bat/projects/bream/upstream/otp/erts/emulator/beam/erl_proc_sig_queue.c:10387) [Receiver empty-scan handoff](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/beam/erl_proc_sig_queue.c#L7771-L7798) · [local](/home/bat/projects/bream/upstream/otp/erts/emulator/beam/erl_proc_sig_queue.c:7771)

This is not a liveness acknowledgment. Ordinary notification eventually passes through scheduling's FREE/inactive guard; system scheduling uses FREE as a failure state. Deferred fetch-repair notification stores a PID and redoes live lookup when the callback runs. None authorizes a dead application continuation to resume. [Ordinary scheduling guard](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/beam/erl_process.c#L6935-L6948) · [local](/home/bat/projects/bream/upstream/otp/erts/emulator/beam/erl_process.c:6935) [System scheduling guard](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/beam/erl_process.c#L7160-L7165) · [local](/home/bat/projects/bream/upstream/otp/erts/emulator/beam/erl_process.c:7160) [Deferred relookup](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/beam/erl_proc_sig_queue.c#L1528-L1564) · [local](/home/bat/projects/bream/upstream/otp/erts/emulator/beam/erl_proc_sig_queue.c:1528)

## 3. Flush, deinstallation, death: transition and ownership table

| Transition | Protection and ownership change | Required distinction |
|---|---|---|
| Prepared → selected slot | Caller owns signals; Process and array protected independently. | Array ref does not mean slot remains open. |
| Slot locked/alive → appended | Slot mutex serializes linking and deinstaller; transport owns signals after append. | Receiver may already be EXITING/FREE. |
| Ordinary flush selects bitmap | Flusher clears summaries and exchanges bitmap, then locks selected slots. | Bitmap selection precedes queue transfer; sender recheck covers intervening publication. |
| Slot queue → receiver incoming queue | Under slot mutex, concatenate links and offsets; ordinary flush resets slot queue. | No copying, application consumption or message destructor occurs here. |
| Deinstallation starts | MSGQ-side protocol sets array.alive false, then visits slots separately. | Other slots can still accept until their own alive flags are cleared. |
| Each slot closes | Lock → concatenate nonempty sequence → slot.alive=false → unlock. | Before-lock send is collected; after-close attempt fails without transfer. |
| All slots closed → pointer unpublished | Clear metadata; full-barrier store NULL into published pointer. | An old cached pointer remains usable only under its protection, and every slot is dead. |
| Array retired → final free | Baseline release waits for thread progress; unmanaged refs can delay final release. | Freeing array destroys mutexes/storage, not transferred signals. |
| Receiver death cleanup | Fetch transferred incoming signals; process control signals through exit dispatcher; later release remaining ordinary messages. | Protocol replies/releases cannot be replaced by blindly freeing every signal. |

Ordinary flush clears both type flags, exchanges the bitmap, and visits selected slots in index order. Under each slot lock it concatenates into `sig_inq` and empties that slot. Adaptation may trigger deinstallation after several rounds. Flush is not an atomic snapshot across all slots and does not establish global order across different senders. [Flush and adaptation](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/beam/erl_proc_sig_queue.c#L10494-L10561) · [local](/home/bat/projects/bream/upstream/otp/erts/emulator/beam/erl_proc_sig_queue.c:10494)

Deinstallation takes **every** slot lock, including slots absent from the bitmap. It concatenates each nonempty queue before setting its alive flag false. Unlike ordinary flush it leaves stale queue pointers in dead slots; those are no longer independent owning queues. Final array release only destroys their locks and allocation. Traversing them again as signal owners would double-release transferred contents. [Close and transfer](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/beam/erl_proc_sig_queue.c#L10597-L10640) · [local](/home/bat/projects/bream/upstream/otp/erts/emulator/beam/erl_proc_sig_queue.c:10597) [Final array destruction](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/beam/erl_proc_sig_queue.h#L1956-L1974) · [local](/home/bat/projects/bream/upstream/otp/erts/emulator/beam/erl_proc_sig_queue.h:1956)

After unpublishing, the deinstaller releases its temporary array ref, if any, then schedules the **baseline** decrement through thread-progress cleanup. A non-normal caller first dispatches auxiliary work to normal scheduler 1, because only normal schedulers can queue that cleanup operation. The baseline ref protects the array during this dispatch interval. Managed borrows require the grace period; unmanaged refs can outlive it. [Cleanup callback](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/beam/erl_proc_sig_queue.c#L10581-L10595) · [local](/home/bat/projects/bream/upstream/otp/erts/emulator/beam/erl_proc_sig_queue.c:10581) [Retirement dispatch](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/beam/erl_proc_sig_queue.c#L10642-L10654) · [local](/home/bat/projects/bream/upstream/otp/erts/emulator/beam/erl_proc_sig_queue.c:10642)

Exit removes the process from the table and publishes FREE before it reaches buffer deinstallation. It then holds MSGQ, flushes/deinstalls, fetches incoming signals into private queues, unlocks, processes relationships and runs the exit signal dispatcher. A cached sender that wins its slot lock before closure can therefore publish after FREE, and exit can still collect it. This qualifies report19: its EXITING rejection describes the **ordinary locked fallback**, not all buffered admission. [Removal and FREE](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/beam/erl_process.c#L14455-L14479) · [local](/home/bat/projects/bream/upstream/otp/erts/emulator/beam/erl_process.c:14455) [Exit buffer closure](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/beam/erl_process.c#L14534-L14543) · [local](/home/bat/projects/bream/upstream/otp/erts/emulator/beam/erl_process.c:14534) [Exit dispatcher phase](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/beam/erl_process.c#L14575-L14598) · [local](/home/bat/projects/bream/upstream/otp/erts/emulator/beam/erl_process.c:14575)

The exit dispatcher releases incoming exit/link/monitor representations by type; alternate messages are cleaned up, late monitor/link requests receive their exit-state handling, and internal replies/RPC have dedicated branches. After control handling, `cleanup_queues` releases ordinary messages/markers in inner and middle queues and asserts in DEBUG that outer is empty. It is not an array deinstaller. [Selected exit actions](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/beam/erl_proc_sig_queue.c#L7309-L7365) · [local](/home/bat/projects/bream/upstream/otp/erts/emulator/beam/erl_proc_sig_queue.c:7309) [Reply/control actions](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/beam/erl_proc_sig_queue.c#L7400-L7442) · [local](/home/bat/projects/bream/upstream/otp/erts/emulator/beam/erl_proc_sig_queue.c:7400) [Final queue cleanup](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/beam/erl_proc_sig_queue.c#L9588-L9623) · [local](/home/bat/projects/bream/upstream/otp/erts/emulator/beam/erl_proc_sig_queue.c:9588)

## 4. Ordering across the fast and fallback paths

Same-sender sequential signals hash to the same slot, whose mutex orders appends. Direct publication into `sig_inq` flushes outstanding buffers first when off-heap queues apply. Ordinary single-message fallback explicitly flushes before linking; longer sequences use the same `enqueue_signals` flush rule. Known distributed senders can use a slot; the unknown-sender legacy path flushes instead. [Sender-key slot](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/beam/erl_proc_sig_queue.c#L10284-L10301) · [local](/home/bat/projects/bream/upstream/otp/erts/emulator/beam/erl_proc_sig_queue.c:10284) [Direct-path flush condition](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/beam/erl_proc_sig_queue.c#L825-L835) · [local](/home/bat/projects/bream/upstream/otp/erts/emulator/beam/erl_proc_sig_queue.c:825) [Flush before append](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/beam/erl_proc_sig_queue.c#L896-L909) · [local](/home/bat/projects/bream/upstream/otp/erts/emulator/beam/erl_proc_sig_queue.c:896) [Ordinary fallback](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/beam/erl_message.c#L434-L449) · [local](/home/bat/projects/bream/upstream/otp/erts/emulator/beam/erl_message.c:434) [Distributed boundary](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/beam/erl_message.c#L317-L357) · [local](/home/bat/projects/bream/upstream/otp/erts/emulator/beam/erl_message.c:317)

Pending monitor optimization is part of this ordering chain: a later same-destination control signal prepends the pending monitor, and ordinary messages do likewise. If ordinary fallback discovers EXITING, it restores that prepended control signal to scheduler-pending ownership while cleaning up the messages. “Discard the entire rejected sequence” would lose a monitor protocol obligation. [Control prepend](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/beam/erl_proc_sig_queue.c#L1146-L1166) · [local](/home/bat/projects/bream/upstream/otp/erts/emulator/beam/erl_proc_sig_queue.c:1146) [Message prepend](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/beam/erl_message.c#L462-L479) · [local](/home/bat/projects/bream/upstream/otp/erts/emulator/beam/erl_message.c:462) [Failure separates ownership](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/beam/erl_message.c#L411-L426) · [local](/home/bat/projects/bream/upstream/otp/erts/emulator/beam/erl_message.c:411)

The guarantee is signal order for the same sending entity/destination, not a total order among threads or slot indices. Priority reception can subsequently place messages differently, and selective receive can consume them differently again. Shared synthetic `from` identities do not justify invented ordering between independent native callers. [Signal ordering contract](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/system/doc/reference_manual/ref_man_processes.md#L495-L513) · [local](/home/bat/projects/bream/upstream/otp/system/doc/reference_manual/ref_man_processes.md:495) [Priority placement distinction](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/system/doc/reference_manual/ref_man_processes.md#L376-L389) · [local](/home/bat/projects/bream/upstream/otp/system/doc/reference_manual/ref_man_processes.md:376)

Fetch adds another race repair: after transferring incoming queues and clearing process flags, it rereads the bitmap and summaries. If concurrent publication requires restored work flags, it release-sets them and may schedule a deferred notification. Conservative extra flags can survive until another fetch; missing actual work indefinitely is the prohibited outcome. [Fetch repair](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/beam/erl_proc_sig_queue.c#L1436-L1517) · [local](/home/bat/projects/bream/upstream/otp/erts/emulator/beam/erl_proc_sig_queue.c:1436)

## 5. One unresolved late-installation branch

A source-level closure argument remains incomplete. `proc_queue_signal` locks MSGQ, reads state, and calls `maybe_install_buffers` **before** checking FREE. That helper checks off-heap state, existing array and its heuristic; it does not explicitly reject FREE. Exit's state transition clears suspension/dirty-work flags, and its FREE publication does not itself clear OFF_HEAP_MSGQ. [Fallback order](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/beam/erl_proc_sig_queue.c#L1211-L1227) · [local](/home/bat/projects/bream/upstream/otp/erts/emulator/beam/erl_proc_sig_queue.c:1211) [Installation predicate](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/beam/erl_proc_sig_queue.c#L10658-L10693) · [local](/home/bat/projects/bream/upstream/otp/erts/emulator/beam/erl_proc_sig_queue.c:10658) [Exit state mutation](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/beam/erl_process.c#L13501-L13507) · [local](/home/bat/projects/bream/upstream/otp/erts/emulator/beam/erl_process.c:13501)

Consequently, a retained sender reaching fallback after deinstallation appears able to reinstall an empty array if the heuristic permits; DEBUG's forced-install setting makes the condition especially relevant. The inspected final `delete_process`/`erts_free_proc` path does not contain another array teardown. This is an **unresolved reachability and reclamation candidate**, not a demonstrated leak, use-after-free, or upstream bug. It requires an exact-version pause/instrumentation experiment and full caller/state/ownership analysis; ordinary send-success observations cannot resolve it. A model restricted to retirement of one existing array must state that installation/reinstallation is excluded. [Final body-cleanup entry](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/beam/erl_process.c#L13393-L13406) · [local](/home/bat/projects/bream/upstream/otp/erts/emulator/beam/erl_process.c:13393) [Final record release](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/beam/erl_process.c#L12139-L12149) · [local](/home/bat/projects/bream/upstream/otp/erts/emulator/beam/erl_process.c:12139)

## 6. Evidence limits and proposed cases
