# Persistent local reads: implementation findings

Completed **2026-10-09**. The [source contract](68-persistent-read-source-contract.md) now has an executed [fifteenth implementation milestone](../../experiments/persistent-read/README.md). A host-installed local endpoint survives successive positive reads, and earlier returned bytes remain owned by the process while it waits for later input. Broader G1–G5 qualification remains partial.

The central distinction is between process identity, endpoint ownership and individual request identity. Pinned OTP cancellation checks both the reader PID and operation reference. Bream now assigns every read a nonwrapping identity and checks it during cancellation, readiness dispatch and completion. An old future's destructor or a stale completion cannot affect a newer request on the same live process. A cancelled, already-claimed request remains outstanding until it settles; a new request cannot consume from the endpoint meanwhile. [Source mapping](68-persistent-read-source-contract.md#what-the-pinned-otp-branches-establish), [adapter](../../experiments/persistent-read/runtime/src/stream_read.rs).

The sole driver controls descriptor closure. Process stop requests retirement and wakes the driver; it does not close a descriptor retained in the driver's poll snapshot. A controlled test holds the captured snapshot through process cleanup, verifies that a peer write still succeeds, then resumes a real poll call and checks that it reports no invalid descriptor before retirement. This proves the captured pre-poll boundary, not that the kernel was already blocked when stop happened. Another control closes the peer before draining four bytes, three remaining bytes and EOF. [Internal controls](../../experiments/persistent-read/runtime/src/stream_read/tests.rs).

Public code performs separately gated reads, retains both results through endpoint closure, and checks peer progress while waiting. Six stop cases cover the gaps between reads and a wait during each of three requests. Endpoint capacity remains occupied after result consumption and becomes reusable after owner death. Replacement and shutdown checks settle pending resources with remote peers still open. EOF and failure close this read-only endpoint and are cached; this deliberately excludes BEAM's broader half-close behavior. [Public controls](../../experiments/persistent-read/consumer/src/streams.rs).

Rust moves each completed Vec into checked StreamBytes without another payload copy; a backing-address assertion checks that transfer. This is a structural ownership result, not a speed comparison. Every new request still allocates a buffer, short reads can retain excess capacity, and delivered buffers can coexist with later requests. The sixteen-endpoint limit is therefore not a whole-runtime memory bound. A future buffer-recycling treatment must preserve actor-held bytes and bounded cleanup; the [I/O performance backlog](../performance-plan.md) remains unexecuted here.

The [passing cohort](../../evidence/persistent-read/runs/20261009-stream-01/results.json) records 484 expected command outcomes and 434 aggregate observations. Each compiler profile passes 136 runtime tests, 179 rejected consumers and eleven positive shadowing examples. Six public stream configurations include 96 second-read/kill races. All inherited controls pass, including the BEAM exit reference; no matched Erlang socket fixture was added. The [audit](../../evidence/persistent-read/validation.json) verifies 1,233 hash records, 233 current inputs and preservation of all 219 preceding inputs. Review found no remaining material defect within the declared scope; it prompted the explicit snapshot and peer-closed buffered-data controls. No speed tests ran.

Cancellation remains intent: a ready result can win consumption, and a claimed read may consume bytes before discarding them after stop. Next, define data/timeout arbitration using the existing injected clock, retain claimed storage until settlement, and prevent an old timer from affecting a later read. General cancellation, writes, transfer, multiple workers and driver-panic recovery remain open. [Next milestone](../milestones.md#next-bounded-milestone).
