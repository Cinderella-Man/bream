# Linux readiness and registration lifetime

Source review, 2026-10-07. Reference: OTP **29.1.1**, commit `ad05823719d77c8faee87348ea39513d4e2f99c5`. This extends [report 22](/home/bat/projects/bream/docs/research/22-process-io-native-boundary.md) into `erl_poll.c` and `erl_check_io.c`. Scope is process-associated Linux readiness, registration and cleanup; socket protocols, codecs and other application libraries are excluded. No OTP tests or Bream experiments were executed for this report. Separately retained Linux-only probes are described below; they do not qualify the BEAM integration.

The main finding is that **descriptor ownership, kernel interest, pending notifications and safe closure are distinct lifetimes**. Rust can make some transfers explicit and avoid generic message construction, but an `OwnedFd` does not discharge the reactor's pending work or prove that a notification still describes the current registration.

## 1. The actual Linux path and its state

The inspected path is `enif_select_x → erts_io_control_wakeup → erts_poll_control → epoll_ctl`, then `epoll_wait → erts_check_io → send_select_msg`. Normal pollsets use kernel one-shot operation; the scheduler pollset is created with ID `-1` and explicitly disables `oneshot`. Public NIF notifications remain one-shot through higher-level state. Therefore neither “all ERTS polling is one-shot” nor “ERTS uses edge-triggered epoll” accurately describes this path. `EPOLLET` is used as an internal NVAL bit in the event mapping, not selected as the normal registration policy. [Registration flags](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/sys/common/erl_poll.c#L769-L794), [scheduler pollset identity](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/sys/common/erl_check_io.c#L2546-L2559), [one-shot choice](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/sys/common/erl_poll.c#L2189-L2196), [event mapping](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/sys/common/erl_poll.h#L176-L191).

| State/owner | Meaning | Why it cannot be folded into one “registered” bit |
|---|---|---|
| `state->events` | Directions requested through the public select operation | A requested direction can temporarily be absent from the active kernel set. |
| `active_events` | Directions tracked as active in a pollset | Scheduler polling may retain input interest after application cancellation until a trigger removes it. |
| `driver.nif->{in,out,err}` | Pending recipient and prepared message for each direction | A detached message has left this ownership even if delivery is still pending. |
| `NIF_SELECT` | Read notification in flight for scheduler-poll accounting | Clearing public interest is not the only consumer of this flag. |
| `STOP_NIF` plus resource reference | Stop callback waiting for poll coordination | The retained reference must survive until the safe-close callback. |

These fields and distinctions are explicit in [state definitions](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/sys/common/erl_check_io.c#L76-L105) and [requested/active masks](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/sys/common/erl_check_io.c#L183-L204). Mutations are serialized with an FD-hashed mutex. On continuous-FD builds the state array indexes directly by descriptor number; growing it takes a growth mutex and every FD lock before reallocating and publishing the new length. A sparse high descriptor can therefore change storage and synchronization cost even with few live registrations. [Lock/index/growth](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/sys/common/erl_check_io.c#L248-L305).

## 2. Registration mutation and failure are asymmetric

Concurrent epoll updates go directly to the kernel without waking the waiting thread merely to apply the change. The source expressly allows results for descriptors removed concurrently; `check_io` must deal with them. The backend stores `data.fd`, not a registration-generation token. [Concurrency contract](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/sys/common/erl_poll.c#L37-L61), [stored token](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/sys/common/erl_poll.c#L769-L773).

`epoll_ctl` retries EINTR. On other errors, ADD returns NVAL; MOD first attempts DEL and then returns NVAL; DEL errors are ignored. ADD increments descriptor accounting before the syscall and the failure path compensates it; failed MOD decrements after attempting removal. These are backend policies, not a lossless errno API. Only failed **ADD** is routed into the fallback pollset. [Retry/failure handling](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/sys/common/erl_poll.c#L800-L806), [operation-specific errors](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/sys/common/erl_poll.c#L828-L860), [fallback condition](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/sys/common/erl_check_io.c#L519-L530).

Linux can reject an otherwise valid descriptor because its object does not support epoll; it also reports resource-limit failures. Ownership does not eliminate those errors. [Linux control contract](https://man7.org/linux/man-pages/man2/epoll_ctl.2.html).

There is already a syscall-elision path: adding no newly requested directions avoids a backend call while the per-direction notification may still be replaced. Any Rust benchmark must compare against that behavior, not assume every re-registration makes a syscall. [Mask/control delta](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/sys/common/erl_check_io.c#L1393-L1419).

Report 22's summary of failure rollback needs a narrow reading. `enif_select_x` has a **conditional** reset for an existing NIF state with `old_events == 0`; it is not visibly a general transactional rollback of all masks and ownership. Exact poststates under injected backend failures remain unexecuted here. Do not turn the summary into an invariant unsupported by those branches. [NVAL path](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/sys/common/erl_check_io.c#L1422-L1434).

## 3. Readiness, cancellation and rearming

After polling, dispatch acquires the FD lock and filters returned bits against current `active_events`. An inactive direction can be discarded even though the kernel reported it. Normal poll dispatch clears the triggered directions and rearms any remaining active directions; a failed rearm adds those directions to the current notification set instead of silently leaving them stranded. Scheduler-owned input is excluded from the ordinary poll-thread path. [Filtering/rearming](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/sys/common/erl_check_io.c#L2045-L2091).

The NIF branch detaches pending messages under the lock, clears their stored PID/message pointers and requested bits, then unlocks before sending. Cancellation reports a direction cancelled only while its pending recipient is still present. Consequently a failed-to-cancel observation permits an already detached message to arrive; it does not imply the recipient has consumed it. A successful cancellation applies to that pending request, not future rearming. [Detachment](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/sys/common/erl_check_io.c#L2121-L2155), [send after unlock](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/sys/common/erl_check_io.c#L2168-L2179), [cancel flags](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/sys/common/erl_check_io.c#L1466-L1483).

Errors have a further state product. ERTS maps both EPOLLERR and EPOLLHUP to its error mask. Without `WANT_ERROR`, an error activates the currently selected active directions, rather than inventing an unrequested callback. With that flag, dispatch uses the ordinary mask-filtering branch and can detach a separately requested error notification. The flag is set when error interest is added and explicitly cleared on STOP; ordinary error cancellation does not clear it here. Cancellation therefore does not establish restoration of implicit read/write fanout. The history “request error → cancel error → later HUP with read interest” requires a targeted reference fixture. [Error fanout](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/sys/common/erl_check_io.c#L2018-L2045), [flag set](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/sys/common/erl_check_io.c#L1393-L1408), [flag cleared on stop](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/sys/common/erl_check_io.c#L1514-L1519).

HUP does not authorize discarding unread data: Linux documents that outstanding bytes can precede EOF. Readiness is a prompt to attempt qualified nonblocking I/O, not a completed read or a reservation of bytes. [HUP contract](https://man7.org/linux/man-pages/man2/epoll_ctl.2.html).

## 4. Stop, descriptor reuse and kernel identity

Fallback polling uses queued updates. DEL sets a reset marker, clears interest and wakes the poller; its processed reset produces an `ERTS_POLL_EV_NONE` result. That result is meaningful control acknowledgment even though it carries no read/write direction. `STOP_NIF` consumes it and invokes the resource stop callback outside the FD lock before releasing its retained reference. The epoll path normally needs no such wake and can call stop directly after deletion. [Deferred update](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/sys/common/erl_poll.c#L1405-L1420), [poll reset result](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/sys/common/erl_poll.c#L1161-L1195), [direct/deferred decision](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/sys/common/erl_check_io.c#L1485-L1513), [deferred completion](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/sys/common/erl_check_io.c#L2182-L2192), [callback/release](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/sys/common/erl_check_io.c#L2230-L2247).

A pending-stop conflict has defensive branches: a new selection or a different stop owner can cancel the old pending callback and release its reference, logging the conflict. This must not be promoted into a supported “reuse before stop completes” API. The documented resource association ends only after the stop callback returns. [Pending-stop handling](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/sys/common/erl_check_io.c#L1815-L1844), [association contract](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/doc/references/erl_nif.md#L3577-L3594).

Linux interest-list identity combines a descriptor number and its open file description. Duplicating a descriptor can keep the description and registration alive after the original number closes. Already copied event arrays also survive deletion. A generation token would help a proposed Rust reactor reject an obsolete registration, but it would be a new representation choice—not an existing BEAM mechanism demonstrated here. [Linux registration lifetime and cached events](https://man7.org/linux/man-pages/man7/epoll.7.html).

For Linux close errors, blindly retrying can close an unrelated descriptor that reused the released number. Correct ownership needs platform-specific close semantics as well as registration coordination. This report does not claim all close paths or callbacks have bounded latency. [Linux close contract](https://man7.org/linux/man-pages/man2/close.2.html).

## 5. Notification allocation and scheduler-poll migration

`prepare_select_msg` first discards any pending message being replaced. A custom message with a supplied NIF environment transfers that environment into a message; without one, it sizes and copies the term. The default path allocates a tuple and resource/reference terms. Scheduler-poll read notifications additionally carry a saved message and raw event number, traveling as a special process signal. [Allocation/transfer](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/sys/common/erl_check_io.c#L714-L760), [signal metadata](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/sys/common/erl_check_io.c#L763-L777). A typed Rust notification can plausibly avoid term sizing/copying; it still needs exactly one owner before publication, after detachment and on failed delivery.

Scheduler migration is conditional on enabled scheduler polling, current flags and repeated read rearming. A changed recipient resets the counter; with the same recipient, `++count > 10` enters the migration branch. Rearming clears in-flight accounting and removes the FD from the current scheduler's saved list so an old entry cannot clear a newly triggered flag. [Eligibility/counter](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/sys/common/erl_check_io.c#L1353-L1375), [rearm cleanup](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/sys/common/erl_check_io.c#L1377-L1389).

When signal handling has no free scheduler tracking slot, it clears the in-flight flag immediately. Failed send also clears the flag and releases the message. The source comment mentions resetting a poll counter in one path, but the called helper shown here clears the flag and decrements outstanding-I/O accounting; it does not itself reset `count`. The code, rather than that comment, defines the traced effect. [Clear helper](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/sys/common/erl_check_io.c#L782-L798), [slot exhaustion and send failure](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/sys/common/erl_check_io.c#L814-L845).

## 6. Wakeup, retry and dispatch work

Wakeup writes are coalesced through an atomic wake state: only the transition from not-woken writes the pipe. Writes retry EINTR and tolerate a full nonblocking pipe; other failures are fatal. The reader drains it, and internal wake/timer results are removed or marked invalid before FD dispatch. These events must not masquerade as application readiness. [Wakeup protocol](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/sys/common/erl_poll.c#L429-L459), [drain](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/sys/common/erl_poll.c#L464-L485), [result filtering](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/sys/common/erl_poll.c#L1490-L1501).

A zero-result wait can repeat until its absolute monotonic deadline; EINTR is returned to the check-I/O layer, whereas EAGAIN restarts there. A configured timerfd supplies sub-millisecond waits to epoll and is cleared after waiting. These distinct exits are not an unconditional relative-timeout retry loop. [Wait/deadline loop](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/sys/common/erl_poll.c#L1949-L1968), [timerfd path](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/sys/common/erl_poll.c#L1857-L1870), [clear](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/sys/common/erl_poll.c#L571-L586), [caller errors](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/sys/common/erl_check_io.c#L1971-L1989).

The result array starts from a 512-event constant and doubles when filled, capped by state-table length. The loop processes the returned batch before that growth decision; these lines do not establish a per-iteration application scheduling or kill-latency bound. Fallback poll scanning separately remembers its last index to avoid always starting at the same descriptor. [Initial constant](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/sys/common/erl_check_io.c#L142-L156), [batch growth](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/sys/common/erl_check_io.c#L2250-L2267), [fallback cursor](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/sys/common/erl_poll.c#L1529-L1535), [cursor update](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/sys/common/erl_poll.c#L1561-L1578).

## 7. What Rust can establish earlier

`OwnedFd` closes its descriptor on drop, excludes another owner closing that same descriptor through the supported ownership contract, and can expose a lifetime-bound `BorrowedFd`. It does **not** imply exclusive access to the underlying open file description: `try_clone` deliberately shares that description. [OwnedFd](https://doc.rust-lang.org/std/os/fd/struct.OwnedFd.html).

`BorrowedFd<'a>` guarantees the descriptor remains open for that borrow. Its documented FFI use excludes capture/consumption of the descriptor. A registration lasting beyond the call needs an owner retained by the runtime or an appropriately enforced longer lifetime; passing a short borrow to `epoll_ctl` does not make the kernel registration expire with that borrow. [BorrowedFd](https://doc.rust-lang.org/std/os/fd/struct.BorrowedFd.html).

Possible Rust-specific gains, all hypotheses:

- A consuming registration API can move closing authority into a runtime-owned record, avoiding application-level duplicate ownership and some defensive misuse paths. It cannot remove kernel errors, stale results, recipient lookup, duplicate-description effects or independent process-kill cleanup. Safe forgetting of application handles remains covered by [report 41](/home/bat/projects/bream/docs/research/41-rust-guarantees-and-process-admission.md).
- Private typed states can distinguish open/closing/closed ownership and represent pending messages as owned optional values. Read/write/error interests and in-flight accounting remain orthogonal concurrent state; one linear enum is not their whole protocol.
- Typed envelopes may replace generic term construction and reference decoding. Replacing a pending envelope still must reclaim it, and a detached envelope cannot be reused while the mailbox owns it.
- A generation-tagged stable slot could separate registration identity from the raw descriptor, potentially allowing cheaper lookup than an ownership-heavy pointer token. Generation rollover, retained batches and slot reuse remain runtime proof obligations. Rust does not synthesize that protocol.

The same representation changes could be implemented in C/C++; Rust adds useful ownership and privacy checks at the interfaces. No language-level guarantee makes the syscall or cleanup protocol free. Linux/Rust documentation was checked on 2026-10-07; these live documentation links are not pinned OTP sources.

## 8. Six proposed performance experiments

All planned. Require matching supported observable behavior, no reintroduced blocking application calls, complete kill/cleanup accounting and retained stale-event tests before comparing speed. Report syscall counts, allocations, retained bytes, lock waits, CPU, p50/p99/max latency and time to final registration release separately.

| Experiment | Baseline → treatment | Workload and acceptance controls |
|---|---|---|
| IO-42.T01 — Notification representation | Dynamically built generic envelope → inline typed notification with owning registration token | Repeated rearm, replacement-before-ready, cancellation and receiver death; require lower measured allocation/copy cost without reusing a detached payload. Compare against the existing no-new-interest syscall elision. |
| IO-42.T02 — Registration storage | Dense FD-indexed table with striped-lock growth → chunked stable slots/generation handles | Sparse high FD values, burst growth and close/reuse; measure peak storage and growth pauses. All published records must remain valid; stale keys must not resolve to a different resource. |
| IO-42.T03 — Rearm work | Correct immediate one-shot rearm → coalesced changes within an explicit publication protocol | Simultaneous read/write, rapidly replaced recipients and cancellation; count control syscalls, then reject any lost wakeup or delayed direction caused by collapsing the wrong masks. |
| IO-42.T04 — Poll placement | Dedicated poll threads → optional scheduler-local read polling | One hot owner versus alternating owners and independent cold FDs; measure wakeups/cache locality alongside peer progress and shutdown drain. Include in-flight accounting saturation and migration back. |
| IO-42.T05 — Batch policy | Adaptive growing batch → capped dispatch work with retained continuation | Many ready FDs plus timers, kill and one rarely active descriptor; require useful tail-latency improvements without lost events, starvation or untracked batch ownership. |
| IO-42.T06 — Wake transport | Existing coalesced pipe protocol → qualified alternative notification primitive | Many producers, empty/full transitions, interrupted syscalls and shutdown; compare syscalls/CPU while proving no lost wakeup. An alternative primitive is an experiment, not a selected backend. |

## 9. Evidence, new cases and remaining gaps

Selected upstream assertions were read, not run: repeated select/replacement and custom-message environments ([NIF tests](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/test/nif_SUITE.erl#L898-L905), [replacement tests](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/test/nif_SUITE.erl#L979-L1005)); scheduler migration with simultaneous write interest and cancelled read ([tests](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/test/nif_SUITE.erl#L1088-L1130)); explicit error cancellation/rearm ([tests](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/test/nif_SUITE.erl#L1242-L1276)); actual fallback-set use ([test](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/test/driver_SUITE.erl#L879-L911)). Timing-based suite tests do not enumerate all interleavings.

The parent investigation separately executed five sequential Linux contract families at `-O0` and `-O2`: ten executions with expected results. They observed a copied event surviving DEL/close while its numeric FD was reused; registration surviving original close with a duplicate open; EAGAIN after another read consumed readiness; one-shot disabling and MOD rearm; and unread bytes preceding EOF with HUP. [Fixture](/home/bat/projects/bream/evidence/io-lifetime-review/epoll_contract.c), [recorded results](/home/bat/projects/bream/evidence/io-lifetime-review/probe-results.json). These are Linux-only observations. They do not execute ERTS's masks, callbacks, concurrent locks or failure paths. Their event tokens are deliberately different from BEAM's raw-FD token.

IO-01.C01–C08 already cover the broad lifecycle; report 44 reserves C09–C16. The following nine IDs were reserved for this source pass. **All remain planned Bream cases**, with the limited Linux observations above supporting only parts of C19/C20.

| Case | Trigger and reference branch | Required qualification / forbidden outcome |
|---|---|---|
| IO-01.C17 | Concurrent FD-table growth, sparse high FD and rejected bounds (§1) | Fully initialized stable registration lookup across growth; no cached pointer into moved state or falsely successful invalid/internal registration. Measure global lock pause. |

Test failed rearm and distinguish backend one-shot from public one-shot. |
| IO-01.C20 | ERR/HUP with/without explicit error interest, then cancel/rearm/STOP (§3) | Follow current flags and masks, including sticky WANT_ERROR history; no invented unrequested notification, dropped unread bytes or HUP-as-immediate-EOF assumption. |

| IO-01.C25 | Poll result batch fills repeatedly while cold I/O, timers and process death compete (§6) | Account retained batch work and progress, qualify growth/caps and cleanup latency; throughput alone cannot certify fairness or forced-termination responsiveness. |

Unresolved: exact errno-injected NIF rollback states; complete scheduler-poll migration/error state product; signal-slot reuse interleavings; wake-state reset ordering across all callers; allocation failure during notification replacement; all fallback select/ppoll platform configurations; registration shutdown integration and bounded system-call behavior. A sampled `enif_keep_resource(resource)` argument in the exceptional NONE+deferred-stop branch differs from normal `resource->data` calls; this pass did not establish a valid Linux path reaching it and makes no defect claim. No backend implementation, new I/O API, universal safety proof or measured optimization is selected by this report.
