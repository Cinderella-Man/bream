This pass reads normal-scheduler balancing, migration/stealing consumers, selected wake/spin policy and adjacent test assertions. This deepens the policy calculation left sampled in [report 18](18-process-execution-memory-deep-dive.md). [Report 31](31-receive-parking-wakeup-protocol.md) owns receive parking/activation correctness. Here the question is where eligible work runs, when to redistribute it, and what that costs. ## 1. Balancing is a policy snapshot, not shortest-queue dispatch

Normal scheduling checks reduction-accounted balance work, obtains the published migration plan and applies immigration before selecting its next activity. The balance interval constants are expressed in multiples of `CONTEXT_REDS`, not elapsed milliseconds. `check_balance` serializes entry with an atomic guard; a half-time pass records which schedulers were waiting and resets the next check. A full pass locks each run queue in turn to sample per-priority maximum lengths, reductions and history. This is not one simultaneous global snapshot. [Scheduling entry](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/beam/erl_process.c#L9798-L9822), [interval constants](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/beam/erl_process.c#L59-L65), [entry/half-time](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/beam/erl_process.c#L4894-L4959), [snapshot](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/beam/erl_process.c#L4966-L5002).

The newly traced calculation has these branches:

| Branch | Actual policy calculation | Implication for a Rust experiment |
|---|---|---|
| Queue ran out of work | Per-priority availability is 100; half-time evidence distinguishes partial activity; a nominal full interval updates history. | Empty now and consistently underloaded are different signals. |
| Busy queue with no accounted reductions | Availability becomes zero. | Zero samples are a real branch, not evidence of an infinitely fast worker. |
| Busy queue with reductions | For each process priority, availability discounts consumption by preceding maximum/high priorities; ports are handled separately. | Equal queue lengths can hide unequal service capacity. |
| Default compaction, not forced, some schedulers partly idle | Estimate the active worker count from consumed reductions/history; clamp to at least the half-full count and at most online queues. | Fewer active workers is intentional policy, not necessarily failed stealing. |
| Recent expansion | Preserve the newly increased active count; subsequent shrink can be suppressed when maximum length and reductions remain at least 90% of the recorded rise. | Hysteresis prevents immediate reversal of a useful expansion. |
| All active | Normalize availability using reduction history, compute availability-weighted target maximum lengths and per-priority migration limits. | This is history-weighted planning, not an exact live queue-length equalizer. |
| Utilization balancing enabled/supported | With idle capacity, use utilization instead of queue lengths, ignore small deviations, and keep all online queues active. | An alternate policy, not an additional property of default compaction. |

Sources: [availability branches](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/beam/erl_process.c#L5010-L5066), [utilization/compaction/hysteresis](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/beam/erl_process.c#L5068-L5158), [weighted targets](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/beam/erl_process.c#L5159-L5214), [history calculation](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/beam/erl_process.c#L4757-L4768), [utilization deadband](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/beam/erl_process.c#L5220-L5248). Local entry: [check_balance](/home/bat/projects/bream/upstream/otp/erts/emulator/beam/erl_process.c:4894).

For each priority, queues are sorted by maximum-length-minus-limit. Excess and deficit queues are paired; when one side has more candidates, remaining paths reuse candidates from the other side. Zero service availability can produce evacuation flags. Compacted inactive queues instead receive emigration paths to `queue_index % active_count`. These calculations establish candidate routes, not an immediate relocation of every queued process. [Pairing](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/beam/erl_process.c#L5252-L5346), [inactive paths](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/beam/erl_process.c#L5133-L5150).

The documented default is compaction; utilization balancing is disabled by default and requires a supported monotonic high-resolution clock. Comparing Bream with an Erlang run without recording these settings would confound policy and implementation. [Reference settings](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/doc/references/erl_cmd.md#L1114-L1124), [utilization mode](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/doc/references/erl_cmd.md#L1287-L1303).

## 2. Migration consumers recheck conditions and preserve ownership

Emigration at enqueue time treats evacuation specially. A plan marking the source inactive must recheck the current inactive flag before forcing movement. Ordinary length-based movement requires source above its limit and destination below its limit. Utilization mode additionally requires the destination to be nonempty-flag clear and its current utilization below the destination limit. Immigration uses complementary current-length tests, permits draining inactive/evacuated sources, and is disabled for the utilization-plan branch. [Emigration](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/beam/erl_process.h#L2486-L2549), [immigration eligibility](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/beam/erl_process.c#L4070-L4112).

For processes, immigration releases the destination lock, takes the source lock and searches for an entry at the requested queue priority whose run-queue assignment can change. It unlinks under the source lock, then inserts under the destination lock; it moves at most one eligible process per selected priority in this pass. Low priority shares the normal physical list, so checking the entry's stored priority matters. Assignment CAS refuses a bound process. [Transfer loop](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/beam/erl_process.c#L4115-L4210), [bound check](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/beam/erl_process.h#L2711-L2732).

New plans are built separately, preserve offline entries, and are atomically published before per-queue statistics/flags are reset. Old plan allocations are retired through thread-progress epochs; some return to a preallocated cache-aligned pool. A Rust port cannot replace this with an unprotected pointer merely because updates are infrequent. [Publication/reset](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/beam/erl_process.c#L5353-L5472), [allocation/retirement](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/beam/erl_process.c#L4783-L4890).

Scheduler suspension/evacuation is a separate branch from load compaction. Evacuation drops obsolete lower-priority representations, including the corresponding lifetime decrement for an inactive-free real record. Bound entries go onto a held list instead of migrating; the dedicated rescheduling helper requeues that list. This pass inspected those helpers, not the complete online/offline controller. [Evacuation branches](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/beam/erl_process.c#L4376-L4462), [held-list rescheduling](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/beam/erl_process.c#L4265-L4284).

## 3. Stealing reduces transfer overhead, but its cap is not a time bound

An empty normal queue first marks itself empty. Suspended destinations do not steal; destinations outside the current active set stop searching. Search starts with inactive queues, then visits active queues cyclically. A contended victim is put onto a retry queue; retrying can put it back again. After giving up, the worker reacquires its own queue lock and rechecks for locally arrived work. This is neither random victim choice nor a proven fixed-cost search. [Candidate lock/retry](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/beam/erl_process.c#L4620-L4636), [search/recheck](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/beam/erl_process.c#L4640-L4715).

At a victim, the highest available priority group is considered first; normal and low counts are combined for their shared list. The transfer quota is half the group's length rounded up, capped at 100. The first stolen process is returned directly to the dispatch path; remaining entries are appended to the destination, preserving work that arrived while its lock was released. Per-priority length changes follow the actual entries moved. [Batch selection](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/beam/erl_process.c#L4489-L4537), [transfer/accounting](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/beam/erl_process.c#L4538-L4591), [direct dispatch](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/beam/erl_process.c#L9905-L9912).

**New qualification:** only successful moves decrement the quota. A long prefix of bound entries can still be scanned under the victim lock; contention retries also lack a fixed attempt count in the inspected loop. The 100-entry cap therefore bounds successful transfer size, not inspected nodes, lock-wait duration or kill latency. A proposed Rust scan/attempt cap would be a new policy experiment with an explicit continuation/fallback obligation, not an already-proved BEAM guarantee. [Skip-without-decrement branch](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/beam/erl_process.c#L4538-L4557), [retry loop](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/beam/erl_process.c#L4699-L4714).

## 4. Empty, inactive and asleep are different policy states

`NONEMPTY` changes update a global empty-queue count. The source explicitly permits transient double increments for one queue; it is not a linearizable inventory suitable for strong conclusions about system-wide quiescence. The executable-work predicate includes queue masks and miscellaneous work, and changes during halting to exclude ordinary process work. [Empty-count transitions](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/beam/erl_process.c#L2955-L3014), [work predicate](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/beam/erl_process.c#L107-L127).

The empty scheduling path resets wake-other accounting, skips stealing when inactive, rechecks suspension after stealing, and only then enters worker wait. After wait, the scheduler marks the queue nonempty again and returns through activity checks. This distinguishes “no work found,” “policy says remain inactive,” and “scheduler must suspend.” [Empty path](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/beam/erl_process.c#L9881-L9945).

Ordinary run-queue insertion wakes its assigned scheduler. Separately, `wakeup_other_check` accumulates a queue-length/reduction-based score to recruit another worker, decays it when little work remains, and attempts wakeup above a threshold. Recruitment scans empty active queues before trying to activate the next inactive queue, refuses suspended targets, and CAS-increases active count. Reducing recruitment wakeups must never remove the direct wake required for already-published work. [Direct notify](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/beam/erl_process.c#L3914-L3929), [score](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/beam/erl_process.c#L5610-L5641), [activation/wakeup](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/beam/erl_process.c#L3841-L3911).

Busy-wait policy has separate initial event-wait and post-auxiliary-work spin counts. Spin repeatedly checks sleep flags and periodically yields the OS thread; that yield is runtime machinery, not a requirement that application processes yield. Poll-based sleep uses a different branch. Before actual sleep, CAS installs the sleep type only while waiting flags remain valid. The wait loop services auxiliary work and expired timers, coordinating thread-progress activity around sleeping. `medium` normal spin and wake thresholds are defaults here, not universal optimal settings. [Spin loop](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/beam/erl_process.c#L3065-L3083), [sleep-type handshake](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/beam/erl_process.c#L3087-L3112), [wait policy](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/beam/erl_process.c#L3490-L3627), [defaults/configuration](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/beam/erl_process.c#L5795-L5810), [spin settings](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/beam/erl_process.c#L5852-L5888).

## 5. Seven actionable performance experiments

These are proposed tasks, not selected architecture. Start only after the relevant execution/migration/cleanup contract passes correctness tests. Use identical admitted computations, quantum/accounting policy, process counts, payloads and host conditions for each comparison. Record CPU topology/affinity, worker count, compiler/profile, runtime configuration and workload phase. Include steady CPU loops, many mostly-idle room/session processes, synchronized message bursts, skewed hot rooms, uneven handler costs, and kill requests during load.

For every experiment report throughput, per-process progress distribution, ready-to-run and message latency distributions, kill-to-computation-stop and stop-to-`Down` separately, CPU time, migrations, queue/lock contention and allocation counts. Record reclamation completion separately from stopped execution. Performance acceptance requires reproducible benefit beyond run variance and no correctness failure; define the workload's regression tolerance before results are inspected. No fixed latency guarantee or arbitrary process quota is proposed.

| Task | Baseline → treatment and mechanism hypothesis | Measurements and acceptance/rejection |
|---|---|---|
| **SCHED-P01 — Measure queue locality** | Qualified single shared runnable queue → per-worker queues with the same execution-claim protocol and conservative stealing. Hypothesis: fewer contended operations and warmer resident state. | Measure lock/CAS retries, migrations, cache misses where supported, throughput and tail service delay across uniform/skewed loads. Accept only repeatable benefit without stranded hot queues or worse agreed fairness; reject if benefit comes from less frequent preemption/control checks. |
| **SCHED-P02 — Separate successful-batch and scan budgets** | One-entry steal → half-queue batches with several finite caps; separately test a visited-node/failed-attempt cap with remembered continuation. Include long bound prefixes and contended victims. | Measure inspected nodes, failed locks, transfers per acquisition and longest observed critical sections. Reject caps that repeatedly abandon eligible suffixes or make kill/control work wait behind an unresumable search. The BEAM 100 cap is a comparison point, not a Rust default. |
| **SCHED-P03 — Test victim locality** | Cyclic victim search → recent-success preference, then a bounded randomized or topology-local search with a complete fallback. Hardware topology locality is a new hypothesis; this pass has not proved BEAM's index order is NUMA-aware. | Measure unsuccessful probes, remote traffic/cache misses and hot-queue drain time. Reject locality bias that hides work on distant queues or systematically disadvantages the same processes. Keep random seeds and topology in the record. |
| **SCHED-P04 — Compare compaction and expansion hysteresis** | All qualified workers active → underload compaction with recorded history and delayed shrink after expansion. Keep direct wakeups unchanged. | Alternate idle periods, sudden bursts and sustained uneven work. Measure idle CPU/energy where available, active-worker count, wakeups, migrations and first-burst tail latency. Reject oscillation, slow recovery or kill progress depending on a sleeping worker that policy never reactivates. |
| **SCHED-P05 — Measure balancing information cost** | Live queue-length thresholds → sampled high-water/reduction history; separately add elapsed service-cost estimates. Change cadence and statistic independently. | Measure balance-pass CPU/lock hold time, estimator overhead, workload skew and tail delay. Reject if sampling cost exceeds migration savings or stale plans push work toward newly overloaded workers. Do not treat measured duration as the preemption mechanism. |
| **SCHED-P06 — Tune recruitment and spinning independently** | Immediate recruitment with zero spin → score-based recruitment and a small spin sweep, one factor at a time. Preserve sleep-state handshakes and timer/auxiliary service. | Measure wake syscalls, idle CPU, host oversubscription, wake-to-run delay and burst tails. Reject a throughput gain bought by busy-spinning away host capacity, missed wakeups, delayed timers or worse kill tails outside the predeclared tolerance. |
| **SCHED-P07 — Profile migration-plan publication** | Simple protected configuration reads → immutable published snapshots with an independently justified reader-lifetime mechanism, only if profiling shows read contention. | Measure lookup cost, update cost, retained retired-plan bytes and shutdown/reclamation time. Reject premature retirement, update stalls or accumulation under a stalled reader. The ERTS cache-aligned pool/epochs are evidence for lifetime obligations, not a prescribed Rust ownership design. |

All seven preserve the user's automatic preemption and safe-kill requirements. Scheduler balancing cannot make an admitted uninterruptible native operation stoppable. “More work completed” is a failed optimization result if a CPU hog starves unrelated normal-priority processes or a stopped incarnation later resumes. Conversely, public maximum/high/low priorities and scheduler binding remain later reference features; absence of those APIs must not be presented as failing the initial normal-priority profile.

The official wake-threshold documentation itself describes the early-wakeup versus work-bouncing tradeoff, supporting measurement rather than copying a default. [Threshold tradeoff](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/doc/references/erl_cmd.md#L1326-L1335). Normal-scheduler wake also deliberately expects the run-queue lock not to be held for performance; instrumentation should distinguish time in wake calls from time protecting queue state. [Wake lock expectation](https://github.com/erlang/otp/blob/ad05823719d77c8faee87348ea39513d4e2f99c5/erts/emulator/beam/erl_process.c#L3728-L3743).

## 6. New branch cases and evidence boundaries

At allocation, `features.json` ended at `EXEC-07.C04` (`EXEC-01.C15`, `EXEC-08.C22`). These **eight proposed cases** refine later multiworker qualification; no shared plan/index was edited. Initial invariants such as no post-stop execution still apply when their later mechanisms are enabled.

| Case | Trigger / branch to control | Required observation or unresolved oracle |
|---|---|---|
| EXEC-07.C05 | Victim list begins with bound entries and has eligible work later; successful-transfer quota remains positive. | Bound assignment is preserved; moved entries and counts match. Measure scans separately from transferred count. No inference that the batch cap bounds delay; proposed scan continuation needs its own progress proof. |
| EXEC-07.C06 | Victim remains contended and is re-added for retry while local work arrives or destination becomes suspended. | On returning/rechecking, preserve local work and suspension handling. Characterize retry duration; reject a Rust retry policy that strands input or has no route back to required control work. |
| EXEC-07.C07 | Steal from mixed normal/low list, return first entry directly, append remainder while another producer inserts local work. | Correct per-priority accounting, no lost local tail and one application owner. Do not require an invented global FIFO or instantaneous global priority winner. Public priority variants remain conditional. |
| EXEC-07.C08 | Compaction plan marks queue inactive; recruitment reactivates it before enqueue consumes that plan. | Recheck live inactive state; preserve eligible work under either safe route. Compare burst recovery/hysteresis without requiring exact worker counts or elapsed-time deadlines. |
| EXEC-07.C09 | Higher-priority consumption leaves zero lower-priority availability; migration plan selects evacuation or no capacity. | Preserve priority/accounting semantics and all retained work. Do not claim unconditional fairness across sustained higher priorities; normal-priority peer progress remains the initial requirement. |
| EXEC-07.C10 | Queue evacuation sees bound entries, obsolete proxies and an inactive-free real record; resume races lifecycle cleanup. | Held entries are requeued through the controller; obsolete representations release exactly their owned lifetime protection; dead application computation never resumes. Full controller interleavings remain unexecuted. |
| EXEC-07.C11 | Reader retains old migration plan across new publication/statistics reset; online set changes and reader stalls. | Old memory remains valid until protection ends; offline plan state remains coherent. Test retirement and host shutdown separately; no bare-pointer reuse. |
| EXEC-07.C12 | Empty/nonempty accounting crosses steal search, recruitment and spin-to-sleep; include transient counter overcount and halting/suspended flags. | Approximate counters cannot justify discarding published work; wake/sleep flags preserve notification and permitted work classes. Treat recruitment/spin settings as policy, not a correctness substitute. |
