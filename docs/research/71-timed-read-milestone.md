# Timed persistent reads: implementation findings

Completed **2026-10-09**. The [source contract](70-timed-read-source-contract.md) informs the [sixteenth implementation milestone](../../experiments/timed-read/README.md): a persistent local read can time out, settle and be followed by another read while earlier returned bytes remain live.

Pinned OTP serializes receive and cancellation under the socket's read lock. Its finite wrapper preserves one deadline, but successful primitive reads can return without a final deadline check. Bream therefore makes the arbitration explicit: pending expiry commits Timeout; expiry during a claimed attempt records intent and waits for settlement. A claimed positive result, EOF or failure wins; WouldBlock, Interrupted or a skipped attempt becomes Timeout. Once the process receives Timeout, the old request no longer owns an outstanding syscall and a new request can begin. This is a narrower source-informed policy, not a hard deadline or exact socket:recv equivalence. [Pinned paths and distinctions](70-timed-read-source-contract.md#proposed-bream-arbitration).

The [typed timer service](../../experiments/timed-read/runtime/src/timer.rs) separates mailbox and stream destinations. A deadline, process identity and numeric generation alone would collide when both domains independently use generation one. Destination kind now participates in the key, and callbacks validate the exact active request. Controlled tests deliver detached old callbacks after a later read exists and after forced process-slot replacement. They also register equal mailbox/read generations and deadlines and observe independent expiry.

Request settlement remains separate from process termination. A claimed request retains its endpoint and buffer through expiry; another request remains Busy. Stop still suppresses delivery even if a successful read would otherwise win its timeout race. Timer registrations are removed on completion, abandoned futures and driver retirement. State locks are released before mailbox notification, and timer callbacks run outside the clock lock. [Runtime and controls](../../experiments/timed-read/runtime/src/stream_read/timed_tests.rs).

The [public sequence](../../experiments/timed-read/consumer/src/timed_reads.rs) reads four bytes, times out the next request, reads three later bytes and reaches EOF, while retaining and rechecking the earlier data. Seven stop boundaries cover idle, pending, held-data and returned-timeout states. Open-peer shutdown settles three simultaneous endpoint states. Zero makes one nonblocking driver attempt without a timer; the actor may suspend until that attempt runs. Existing indefinite reads remain timer-free. Finite retries preserve the original injected-clock deadline.

The [six-case BEAM fixture](../../experiments/timed-read/timed_read_reference.erl) checks zero empty/data, finite timeout followed by endpoint reuse, infinity and stale cancellation. It also preserves a deliberate difference: OTP exact-length receive can return partial data alongside timeout, whereas Bream completes on a positive short read. The fixture does not read elapsed time or reproduce the Rust injected-clock interleavings. Internal failure and Interrupted-shaped outcomes are synthetic, and held-request tests qualify controlled arbitration rather than physical interruption inside a kernel syscall.

The first retained cohort exposed an inherited fixture race in the stale-target exit control: it captured `waiting` before the worker incremented `parks`, then expected an unchanged whole snapshot. Only that bookkeeping field changed. The corrected copied fixture waits for an independent peer to complete before capturing its baseline, establishing that the sole worker finished the earlier turn. The failed cohort remains retained; preceding milestone inputs remain untouched. [Failure record](../../evidence/timed-read/runs/20261009-timed-01/results.json).

The [passing cohort](../../evidence/timed-read/runs/20261009-timed-02/results.json) records 517 expected command outcomes and 462 aggregate observations. Each compiler profile passes 153 runtime tests, 189 rejected consumers and twelve positive shadowing examples. Six public configurations include 96 data/timeout and 96 kill/timeout races. Both emulator profiles pass six new socket and thirty-nine inherited exit reference cases. The [audit](../../evidence/timed-read/validation.json) verifies 1,651 hash records across both retained cohorts, 247 current inputs and preservation of all 233 preceding inputs. No speed tests or performance comparisons ran. Review found no material defect in the timed-read implementation within its declared scope. Stop and expiry flags share one Arc allocation instead of requiring two separately allocated flags; buffers still move into typed results without a second payload copy. Requests still allocate, and finite timers retain index storage, so these are structural observations rather than speed claims.

Next: bounded runtime-owned writes, initially consuming returned StreamBytes on the same endpoint. This enables a small echo exchange while forcing explicit treatment of partial writes, backpressure, claimed storage and irreversible external effects after stop. Multiple workers, real-time timers, transfer and general native cancellation remain outside this profile. [Milestone tracker](../milestones.md).
